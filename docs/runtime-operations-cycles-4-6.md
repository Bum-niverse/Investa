# 통합 엔진 운영 4~6차 사이클

## 범위

이 묶음은 실전 주문이나 외부 계좌를 열지 않고 로컬 운영 증거와 복구 준비를 보강한다.

1. 감사 사건을 읽기 전용 JSON으로 내보낸다.
2. Investa가 만든 SQLite 백업의 복원 가능성을 읽기 전용으로 사전검사한다.
3. SQLite와 KRW/USD append-only 모의원장을 자동 점검하고 운영 알림 대응을 화면에서 기록한다.

## 감사 내보내기

- 출력 위치는 현재 앱 데이터 폴더 아래 `exports`로 고정한다.
- 임의 경로를 IPC 입력으로 받지 않는다.
- 한 번에 최대 10,000건을 오래된 순으로 내보낸다.
- 저장 전 모든 사건을 기존 `AuditEvent` 계약으로 다시 검증한다.
- 임시 파일을 동기화한 뒤 최종 파일명으로 변경하며 기존 파일을 덮어쓰지 않는다.
- 결과에는 schema ID, 생성 시각, 사건 수와 전체 JSON의 SHA-256을 포함한다.
- 원본 사건은 수정·삭제하지 않는다. 내보내기 완료 사실은 별도 감사 사건으로 추가한다.

## 백업 복원 사전검사

- 파일명은 `investa-<숫자>.sqlite3`만 허용한다.
- canonical path가 앱 데이터의 `backups` 직계 폴더인지 확인해 경로 이탈과 심볼릭 링크 우회를 거부한다.
- SQLite를 read-only 플래그로 열고 `quick_check(1)`과 `user_version`을 확인한다.
- 현재 앱보다 새로운 스키마, 버전이 없는 파일과 무결성 실패는 복원 차단 사유로 반환한다.
- 감사 사건, 모의원장 사건과 연구 보고서 수를 함께 보여준다.
- 이 단계는 DB 교체를 실행하지 않는다. 실제 복원은 현재 DB 추가 백업, 앱 종료, 격리 복구와 재검증 절차가 완성된 뒤 별도 사용자 승인으로 연다.

## 로컬 상태 자동점검과 알림 대응

- 운영 화면을 열거나 새로고침하면 SQLite quick check, KRW 원장 재생과 USD 원장 재생을 실행한다.
- 각 결과는 5분 유효시간을 가진 공급자 상태 사건 계약에 기록한다.
- 핵심 로컬 구성 실패는 중복 억제된 치명 운영 알림을 만든다.
- 미확인 알림은 운영 화면에서 대응 내용을 입력하고 확인 처리할 수 있다. 치명 알림은 빈 대응을 허용하지 않는다.
- 이 상태는 로컬 저장소와 내부 원장의 준비 상태다. 외부 시세·증권사·거래소 연결이나 실전 주문 가능 상태를 뜻하지 않는다.

## 보안과 데이터 경계

- JSON과 백업에 자격증명을 새로 수집하지 않는다.
- 감사 사건의 비밀정보 marker 검증을 내보내기 전에 다시 적용한다.
- 백업 검사는 원본 파일을 쓰기 가능 모드로 열지 않는다.
- 외부 주문 함수와 실전 주문 잠금은 변경하지 않는다.

## 검증 기준

- 내보낸 JSON을 다시 파싱하고 사건 수·schema·SHA-256 형식을 확인한다.
- 내보내기 뒤 기존 감사 사건의 내용과 존재가 유지되는지 확인한다.
- 사전검사 전후 백업 파일 크기가 같은지 확인한다.
- `../`와 임의 파일명을 거부하는지 확인한다.
- 로컬 자동점검이 SQLite·KRW·USD 3개 구성요소를 모두 기록하는지 확인한다.
- 전체 Rust 테스트, 프런트 타입 검사·빌드, 공개 Upbit 회귀 백테스트와 Tauri 번들을 다시 검증한다.
