# 통합 엔진 운영 3사이클

## 범위

이번 묶음은 학습 모델이나 외부 주문 어댑터가 아니라, 검증된 통합 엔진 결과가 안전하게 내부 모의원장에 도달하고 장애 후 복구되는 운영 경로를 완성한다. 실전 주문 전송은 계속 컴파일 경계에서 비활성화한다.

## 1사이클 — 엔진 결과를 내부 모의주문 후보로 승격

- `completed`, `candidateReady`, 결정론적 pre-trade 승인을 모두 확인한다.
- 엔진 `runId`, 종목, 시장, 통화, 방향, 최종 수량, 기준가, 유효기간과 적용 비용을 후보에 고정한다.
- 동일 실행의 후보는 한 번만 만들 수 있다.
- 사용자 승인 전에는 원장 체결이 발생하지 않는다.
- 승인 후에도 KRW·USD 내부 append-only 원장만 사용하며 실전 주문은 호출하지 않는다.

## 2사이클 — 상태 전이·대사·알림

- 후보의 생성·안전 승인·사용자 승인·제출·체결·기각·만료를 별도 사건 원장에 저장한다.
- 원장 체결 뒤 상태 갱신 전에 앱이 종료된 경우 `submitted`를 `filled`로 복구한다.
- `filled` 상태인데 대응 원장 사건이 없으면 자동 수정하지 않고 치명 알림을 만든다.
- 같은 운영 알림은 15분 동안 병합하고 발생 횟수를 누적한다.
- 치명 알림을 확인하려면 대응 내용을 기록해야 한다.

## 3사이클 — 상태 신선도·감사·백업

- 공급자·원장 구성요소별 최신 상태만 사용한다.
- 마지막 정상 상태가 5분을 넘으면 만료로 처리해 자동운용 준비를 차단한다.
- 감사 사건은 행위자·대상·상관 ID·시각을 요구하며 비밀정보 표식을 거부한다.
- 백업 대상 경로는 앱 데이터의 `backups` 폴더로 고정하고 기존 파일을 덮어쓰지 않는다.
- SQLite `VACUUM INTO`로 스냅샷을 만들고 `quick_check` 통과 뒤 감사 사건을 남긴다.

## UI

`모의 원장·성과 > 성과 분석`에서 다음 작업을 수행한다.

- 후보 준비가 끝난 엔진 실행을 내부 모의주문 후보로 생성
- 후보 승인·기각
- 내부 원장 대사
- 검증 백업 생성
- 공급자 상태와 운영 알림 확인

후보 준비는 주문 체결이 아니다. `내부 모의체결 승인`을 눌러야 원장에 반영된다.

## 검증 결과

- Rust: 153개 중 149개 통과, 외부 자격정보 통합 4개 ignored
- 공개 Upbit 백테스트: 199봉, +62bp, MDD 141bp, 5거래, 승률 40%
- 위험 오버레이: +71bp, MDD 82bp
- TypeScript·Vite 프로덕션 빌드 통과
- Rust 포맷과 Clippy 통과. 기존 모듈 경고 7종은 별도 기술부채다.

백테스트 수치는 연결·계산 회귀검사 결과이며 전략 채택이나 미래 성과의 근거가 아니다.
