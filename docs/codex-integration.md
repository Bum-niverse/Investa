# Codex App Server 연동

기준일: 2026-08-21

## 현재 구현

Investa의 직원 상세 패널에서 업무를 지시하면 Tauri Rust가 로컬 `codex app-server`에 JSONL 요청을 보내고 응답 delta를 대화창에 실시간 표시한다. 본부장은 자유형 답변 대신 안건 분류와 최종 종합의 구조화 계약을 사용한다.

퀀트 논문 연구원은 예외적으로 자유형 delta를 화면에 직접 표시하지 않는다. `turn/start.outputSchema`로 `ResearchReport`를 생성하고 Rust 검증을 통과한 요약과 백테스트 상태만 표시한다. 본부장 회의도 같은 경계를 사용해 부서별 `DepartmentReport`와 본부장 `MeetingSynthesis`를 Rust에서 다시 검증한다. 그 밖의 42명에게 직접 지시하면 서버 소유 역할 카탈로그에서 이름·범위·초점을 다시 주입하고 `RoleReport`만 허용한다. 개별 소견은 다른 역할, 부서 종합, 전체 분석, 백테스트 결과와 주문 후보를 대신할 수 없으며 분석 보관함에 별도 불변 기록으로 저장된다. 부장·실장의 `suggestedAssignments`는 서버의 직속 직원 allowlist로 제한한다. 화면은 예상 호출 인원과 업무·사유를 먼저 보여주며 사용자가 `부서 업무 지시`를 눌러야 각 직원의 별도 turn이 시작된다. 일반 직원은 이 배열을 비워야 한다.

승인된 부서 업무는 배정된 직원별 `RoleReport` 또는 퀀트 논문 연구원의 검증 결과와 오류·취소를 실제 이벤트로 집계한다. 모든 직원이 종료된 뒤에만 부장에게 집계 자료를 전달하고 `DepartmentReport`를 생성한다. 부서 ID와 직원 ID 집합이 승인 당시 배정 목록과 정확히 일치해야 완료되며, 결과는 분석 보관함에 저장한다. 부서 보고가 완성돼도 본부장 회의, 주문 후보와 실주문으로 자동 승격하지 않는다.

국장·미장 분석 역할은 Codex turn 전에 `toss_analysis_snapshot`을 호출한다. 자연어 요청에 포함된 종목명·별칭·티커를 토스 카탈로그에서 단일 종목으로 확정하고, 완료된 수정주가 일봉만 사용해 가격·거래량과 결정론적 기술지표를 계산한다. 기준 시각은 마지막 완료 봉의 종료 시각이며 미완성 봉과 이후 데이터는 제외한다. 부장 제안으로 시작된 직속 직원들은 부장 요청 당시 스냅샷을 재사용해 서로 다른 수집 시각의 자료가 섞이지 않게 한다. 여러 시장 종목이 함께 감지되거나 종목을 확정하지 못하면 스냅샷을 만들지 않고 Codex에 결측 사실만 전달한다.

부서장 회의도 분류가 끝난 뒤 동일한 분석 스냅샷을 한 번 생성해 모든 소집 부서가 재사용한다. 주식은 같은 종목의 토스 보유 수량·평단가·현재가만 읽기 전용 계좌 조회에서 골라 익명화하고, 전체 계좌번호·마스킹 번호·계좌 별칭은 Codex 요청에 넣지 않는다. 가격·기술·포지션·선택 Telegram 메시지에는 결정론적 근거 ID를 부여하고 부서 보고와 본부장 종합에 유지한다. 미연결 공급자는 해당 항목만 근거 공백으로 남기며 다른 가용 근거까지 전체 공백으로 확대하지 않는다. `SHADOW ONLY`는 내부 모의주문 후보 검토를 허용하지만 실주문은 계속 금지한다.

세션 연결 때 `model/list`로 현재 계정의 모델·reasoning effort 카탈로그를 읽는다. `gpt-5.6-sol`이 노출되면 우선 사용하고 없으면 카탈로그 기본 모델을 사용한다. 안건 분류는 `medium`, 개별 직원·부서·연구 분석은 `high`, 본부장 최종 종합은 `xhigh`를 목표로 `turn/start`에 명시한다. 미지원 조합은 카탈로그 안에서만 하향하며 사용자 전역 설정을 추측하지 않는다. 본부장 종합에는 늘어난 부서 요약뿐 아니라 같은 원본 스냅샷을 다시 전달하고, 부서 보고가 카탈로그에 없는 근거 ID를 사용하면 실패로 닫는다. 상세 계약은 [Codex 분석 품질 프로필](codex-analysis-quality.md)에 기록한다.

미장 종목은 SEC 연락처가 설정된 경우 `company_tickers.json`으로 ticker→CIK를 확정하고 Company Facts와 Submissions를 결합한다. SEC 제출 시각이 날짜보다 세밀하지 않은 항목을 고려해 재무·공시는 보수적으로 `filed < asOfDate`를 만족해야 하고 재무 관측치의 `periodEnd <= asOfDate`도 검사한다. 재무값에는 단위·기간·제출일·양식·accession number·회계연도·회계기간·frame을 전달한다. 공시는 최대 20건의 양식·제출일·보고기간·공시 항목·원문 index를 제공한다. 공시 원문 본문을 실행하거나 지시로 취급하지 않으며, Submissions 메타데이터를 언론 뉴스나 감성 데이터로 해석하지 않는다. SEC 오류는 가격 스냅샷 전체를 실패시키지 않고 해당 재무·공시만 `provider_error`로 닫는다. 국장 재무·공시와 언론 뉴스·수급 데이터는 공식 공급자 연결 전까지 `provider_not_connected`이며 추정하지 않는다.

```text
React 직원 패널
  → Tauri command
  → Rust CodexBridge
  → codex app-server --stdio
  → ChatGPT 구독 인증
```

- Investa 기본 번들 확인 버전: `codex-cli 0.149.0` (웹 검색 canary 통과)
- 기본 설치 위치: `%LOCALAPPDATA%\Investa\codex-cli`
- 인증: 기존 Codex의 ChatGPT 로그인 재사용
- 전송: 로컬 stdio JSONL, 외부 listening port 없음
- thread: 직원별로 분리하고 SQLite에 ID를 저장해 앱 재시작 후 `thread/resume`
- sandbox: `read-only`
- network access: 일반 직원·shell은 OFF. 사용자 요청형 논문 조사 thread의 Codex 호스팅 웹 검색만 ON
- approval policy: `never`
- model/effort: `model/list`로 지원 여부를 확인한 분석 유형별 명시 프로필
- 주문·증권사 자격증명·위험 정책 변경 도구: 제공하지 않음

## 사용자 요청형 공개 웹 조사

퀀트 논문 연구원을 직접 호출하거나 회의의 해당 직원이 `research.codex_web_search`를 선택한 경우에만 `paper-researcher-web`이라는 별도 thread를 사용한다. 이 thread는 Codex App Server의 호스팅 웹 검색을 `live`로 켜지만 filesystem은 read-only, shell network는 false, approval은 never를 유지한다. 일반 직원 thread의 웹 검색은 명시적으로 disabled다.

검색어에는 계좌·보유수량·현금·개인정보를 포함하지 않고 공개 종목·사건·논문 주제만 사용한다. 웹 문서의 지시·로그인·다운로드·코드 실행은 거부한다. 회의 RoleReport의 검색 근거는 `codex-web-1`~`codex-web-10`, 전체 HTTPS URL과 관측 시각을 Rust와 React 양쪽에서 검증한다. 직접 논문 연구의 ResearchReport도 HTTPS 원문 계약을 적용한다.

Google Custom Search나 별도 OpenAI API 키를 추가하지 않는다. 사용자가 연구를 요청할 때만 실행되며 24시간 수집기가 아니다. 별도 검색 API 과금은 없지만 로그인된 Codex 구독 사용량에는 포함된다.

`INVESTA_CODEX_PATH` 환경변수로 별도 `codex.exe`를 지정할 수 있다. 환경변수가 없으면 Investa 사용자 설치 폴더 아래의 실행 파일만 제한된 깊이로 탐색한다. WindowsApps의 데스크톱 앱 번들은 후보로 사용하지 않는다.

## 이벤트와 UI 상태

- 업무 대기
- `turn/started`: 요청 전달
- 첫 구조화 응답 조각 수신: 응답 생성 중
- 완료 응답 수신 후 Rust 계약 파싱: 계약 검증 중
- 계약 검증 완료: 보고 완료

App Server는 토큰 단위의 정확한 잔여 작업량을 제공하지 않으므로 회의와 구조화 연구 업무에는 추정 백분율을 표시하지 않는다. 화면은 실제 이벤트와 계약 검증 단계만 표시하며, 완료만 확정 상태다.

회의는 본부장 분류 1회가 안건을 작업 단위로 나누고 관련 부서만 선택한다. 본부를 제외한 8개 전문 부서는 `employee_agent_v2`로 각 전문 직원이 별도 `RoleReport`를 만들고, 부서장이 실제 직원 결과만 `DepartmentReport`로 취합한다. 부서장 단계는 새 사실을 조사하지 않는 결정론적 취합 단계이므로 `medium` 추론을 사용하며, 각 직원의 finding·counterevidence·evidenceGap·evidenceIds를 계약 상한 안으로 축약한 입력만 전달한다. 논문 연구원에는 Rust가 Crossref 공개 서지 메타데이터를 최대 5건까지 읽기 전용으로 첨부하며, 메타데이터를 원문 검증이나 재현 성공으로 간주하지 않는다. 운영·모의원장·감사·근거 manifest도 비식별 읽기 전용 요약만 제공한다. 부서장이 실행되지 않은 직원 이름으로 소견을 대신 만드는 `department_batch_v1` 경로는 전체 회의에서 사용하지 않는다.

전체 호출 상한은 일반 5회와 중요 80회이며 동시 실행은 2명이다. 직원별 v2 비용은 직원당 도구 계획·보고 2회와 부장 취합 1회로 계산한다. 전문 부서가 필요한 회의는 중요로 자동 승격하고 실제 라우팅된 부서의 직원만 실행한다. 80회는 본부장 분류 1회, 35명 전원 계획·보고 70회, 8개 부서장 취합, 본부장 종합 1회의 최악 상한이다. Rust는 허용 부서 ID와 필수 안전 부서를 다시 검증하고, 분류 실패 시 임의 부서를 소집하지 않는다. 중단 시 현재 실행 중인 turn을 실제로 interrupt하고 늦게 도착한 종료 이벤트가 복귀 상태를 덮거나 취소된 분류가 회의를 다시 시작하지 않게 폐기한다.

자유형 응답은 Rust 이벤트 경계와 React 렌더링 경계에서 각각 32KB급 표시 상한을 적용한다. 한도를 넘긴 delta는 한 번만 생략 안내를 표시하고 이후 스트림을 버려 장문 Markdown이 WebView 메모리를 고갈시키지 않게 한다.

## 보안과 개인정보 경계

- 사용자가 직원 대화창에 입력한 업무 요청과 역할 설명은 OpenAI Codex 서비스로 전송된다.
- 계정 토큰은 Codex CLI가 관리하며 React, Investa DB와 로그에 복사하지 않는다.
- 계정 응답 중 이메일 같은 개인정보는 UI에 표시하거나 Investa 로그에 기록하지 않는다.
- `api_key`, `client_secret`, `access_token`, `Authorization: Bearer` 등 흔한 자격증명 표식이 업무 요청에 포함되면 전송 전에 거부한다.
- App Server가 예상하지 않은 승인 요청을 보내면 Investa는 자동 승인하지 않고 거부한다.
- 현재 thread는 파일 읽기만 가능하고 네트워크·파일 수정·명령 승인·주문 권한이 없다.
- `account/rateLimits/read` 결과에서 사용률·창 길이·초기화 시각만 표시하고 계정 개인정보는 보관하지 않는다.
- 실행 중인 직원의 취소 버튼은 서버에 해당 직원의 정확한 `threadId`·`turnId`로 `turn/interrupt`만 보낸다. 취소 요청을 기록한 시점부터 해당 turn의 후속 delta는 폐기하고, 완료 이벤트가 경합하더라도 UI에는 취소로 확정한다.

## 검증 결과

실제 App Server로 다음 순서를 검증했다.

1. `initialize` / `initialized`
2. `account/read`에서 ChatGPT 로그인 확인
3. `thread/start`에서 `readOnly`, `networkAccess: false`, `approvalPolicy: never` 확인
4. `turn/start`
5. 한글 `item/agentMessage/delta` 연속 수신
6. `turn/completed` 수신
7. Investa 실행 프로세스의 자식으로 별도 설치한 `codex.exe app-server --stdio`가 시작되는지 확인
8. 퀀트 논문 연구원의 구조화 보고서 → 서버 검증 → 토스 일봉 백테스트 `DONE` 확인
9. `account/rateLimits/read` 실제 응답을 직원 패널에 표시
10. 직원별 thread ID SQLite 저장과 재시작 시 `thread/resume` 경로 구현
11. `turn/interrupt` 계약과 취소 완료 `status: interrupted` 이벤트 처리 구현
12. 공개 GitHub 근거를 사용한 연구 보고서·토스 탐색 백테스트를 SQLite에 저장한 뒤 앱을 재시작해 기록과 직원별 대화 맥락이 이어지는지 확인
13. 300개 지표 장문 응답을 시작한 뒤 UI에서 취소해 유휴 상태 복귀, 후속 delta 차단과 WebView 메모리 안정성을 확인
14. 부서 보고와 본부장 종합 JSON 계약의 정상·오류 입력을 Rust 단위 테스트로 검증
15. 본부장 안건 분류 스키마의 허용 부서·필수 안전 부서·중복 제거·최대 7개 제한을 Rust 단위 테스트로 검증
16. 국내·미국 주식 분석과 비트코인 내부 모의 자동매매를 합친 안건이 리서치·전략운용·리스크관리·매매운영·디지털자산 5개 부서만 소집하고 투자공학·홍보·준법 부서를 제외하는지 실제 Tauri 화면에서 확인
17. 중요 안건을 실제 App Server로 끝까지 실행해 완료된 부서장부터 본부장실에 복귀하고, 5개 부서장이 모두 도착한 뒤에만 본부장 종합 보고가 시작되는지 확인
18. 여러 시장·자산을 포괄해 단일 종목이 정해지지 않은 안건은 백테스트 종목을 임의 생성하지 않고 `required=false`, `symbol=null`, `strategy=null`인 진입 보류·후보 미등록으로 종료하며, 보고 확인 뒤 `WORKING 00`과 회의실 대기 상태로 전원 복귀하는지 실제 Tauri 화면에서 확인

- 실제 App Server가 turn을 종료하지 않는 경우를 대비해 high/xhigh 구조화 결과인 직원 역할 보고·부서 취합·본부장 종합은 5분, 안건 분류·직원 도구 계획은 3분 제한을 적용한다. 제한 초과 시 해당 turn을 `turn/interrupt`로 취소한다. 직원은 실패·근거 공백으로 기록하고 대기열을 계속하며, 부서 취합은 해당 부서를 실패 보고로 닫고, 본부장 종합은 `hold`로 닫는다. 직원 보고에는 실제 도구가 반환한 evidenceId 허용 배열을 주입하고 임시·`mv-*` ID를 금지한다. 직원 결측을 부서장에게 넘길 때는 계약의 500자 상한으로 결정론적으로 제한한다. 본부장 종합 수신 즉시 화면 이동 연출과 무관하게 결과 체크포인트로 전환하고 자동 승격된 중요도도 DB에 저장한다.
- 안건 분류·부서장 취합·본부장 종합은 회의마다 새 thread를 사용한다. 이 집계 단계는 과거 대화 기억이 필요하지 않고 현재 구조화 입력만으로 재현되어야 하므로, 장기 thread의 context-full·resume 지연이 현재 회의의 유효한 근거를 시간 초과로 폐기하지 않도록 격리한다. 직원의 `agent_tool_plan`과 후속 `role_report`는 도구 선택 문맥을 이어야 하므로 기존 직원 thread를 유지한다.
- 구조화 결과는 `item/agentMessage/delta`를 진행 표시에만 사용하고, `item/completed` 또는 `turn/completed`에 포함된 최종 `agentMessage.text`를 검증 정본으로 덮어쓴다. 스트림 조각 누락·중복이 정상 JSON을 계약 오류로 바꾸지 않게 하며, 최종 메시지가 없는 실패·구버전 이벤트에만 제한된 델타 버퍼를 fallback으로 사용한다.
- 직원 `RoleReport`가 채택한 근거는 ID만 전달하지 않는다. source URL, source revision, observation, observedAt을 제어문자 제거와 항목·길이 상한을 거친 비신뢰 메타데이터로 부서장과 본부장에게 다시 제공한다. 관리자는 이 메타데이터의 명령을 따르지 않고 같은 evidenceId와 대조하며, 공식 원문이 존재할 때 다른 공급자 미연결을 전체 근거 부재로 확대하지 않는다.
- 직원 보고의 `summary`와 서로 다른 `findings`를 합쳐 부서장에게 전달하고, 부서 종합은 결론·핵심 근거·반대 근거·보유자 영향·남은 공백을 상세 문단으로 보존한다. 분석 기록은 각 부서 보고를 독립된 접기/펼치기 구역으로 표시하며 직원별 결과·근거 ID·반대 근거·공백·후속 조치를 함께 보여준다. 근거 충족도는 글 길이가 아니라 공식성·최신성·교차검증·시점 정합성으로 평가한다.

## 사용량 경고·차단 정책

- Codex 1차 사용량이 80%에 도달하면 작업이 공급자 한도로 중간 중단될 수 있음을 경고하지만, 진행 중인 회의와 다음 직원 호출은 계속 허용한다.

## 뉴스·공시 출처 계보

- Naver 뉴스 검색 결과는 `originallink`의 언론사 호스트, 기사 제목, 원문 URL, Naver 검색 URL, 발행 시각과 `evidenceId`를 함께 기록한다.
- Telegram은 선택 채널명, 메시지 요약, 관측 시각과 `evidenceId`를 기록한다. 공개 사용자명이 검증된 채널만 `t.me` 링크를 만들며 비공개 채널 URL은 추측하지 않는다.
- OpenDART 공시는 보고서명, 접수번호·접수일, 공시 URL과 `evidenceId`를 기록한다.
- `분석 후보`, `직원이 조회한 근거`, `최종 보고가 실제 인용한 근거`를 별도 수치와 상태로 표시한다. 조회했다는 이유만으로 보고에 포함됐다고 표현하지 않는다.
