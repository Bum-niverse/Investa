# 통합 엔진 운영 7~9차 사이클

이 묶음은 외부 주문을 열지 않고 로컬 복구 가능성, 재시작 안전 잠금, 백테스트 비교 가능성을 보강한다.

## 7차 — 격리 복구 훈련

- Investa가 생성한 백업만 읽기 전용 사전검사한다.
- 훈련 직전에 현재 운영 DB의 일관 백업을 하나 더 만든다.
- 선택 백업을 앱 데이터의 전용 임시 폴더에 복사하고, 복사본만 최신 스키마로 마이그레이션한다.
- `quick_check`, 감사·원장·연구 기록 수, KRW/USD append-only 원장 재생을 검사한다.
- 성공·실패와 관계없이 새로 만든 훈련 DB·WAL·SHM을 명시적으로 제거한다. 운영 DB를 교체하거나 외부 주문을 보내지 않는다.

## 8차 — 재시작 대사 잠금

- 실제 앱 시작마다 통합 엔진 주문 후보 생성·승인을 잠근다.
- `submitted`·`filled` 후보와 KRW/USD 내부 원장을 대사한다.
- 원장 체결이 확인된 `submitted` 후보는 `filled`로 자동 복구한다.
- 내부 전송 후 원장 체결이 없는 `submitted` 후보는 외부 전송 경로가 없음을 전제로 자동 취소해 중복 재전송을 막는다.
- `filled`인데 원장 체결이 없으면 치명 알림과 사용자 확인 필요 상태를 유지한다.
- 불일치가 0건일 때만 후보 생성·승인을 다시 연다. 실전 주문 전송은 계속 비활성이다.

## 9차 — 편향 감사와 동일 조건 기준선

- 봉의 시간 정렬과 `availableAt`·`ingestedAt`, 신호 다음 봉 체결 시각을 검사해 미래 정보 사용을 차단한다.
- 단일 종목 백테스트로 증명할 수 없는 생존편향과 전체 탐색 횟수를 알 수 없는 데이터 스누핑은 `needs_review`로 명시한다.
- 전략과 같은 종목·기간·통화·초기자금·수량·수수료·세금·슬리피지로 최초 시가 매수·최종 종가 매도 기준선을 계산한다.
- 기존 단순 종가 가격 기준선은 시장 방향 참고용으로 유지하고, 비용 정렬 기준선을 승격 검토의 비교 근거로 사용한다.

## 검증 경계

- 격리 복구는 실제 운영 DB 교체가 아니다.
- 내부 원장 대사는 KIS·거래소 원격 원장 대사를 대신하지 않는다.
- 생존편향과 데이터 스누핑의 `needs_review`를 통과로 바꾸지 않는다.
- 어떤 결과도 수익 보장이나 실전 주문 권한을 뜻하지 않는다.
