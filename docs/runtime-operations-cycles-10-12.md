# 통합 엔진 운영 10~12차 사이클

이 묶음은 외부 계좌 주문과 운영 DB 교체 없이 복구 증거, 저장 실험 편향 감사, 재시작 주문 잠금의 UI 경계를 강화한다.

## 10차 — 백업 목록과 복구 증거

- 앱 데이터 `backups` 폴더 바로 아래의 `investa-<timestamp>.sqlite3` 정규 파일만 최근 100개까지 목록화한다.
- 각 항목은 읽기 전용 `quick_check`, 스키마 호환성, 감사·원장·연구 기록 수와 파일 크기를 함께 표시한다.
- 선택 백업의 사전검사, 해당 백업의 최근 격리훈련 감사 근거와 현재 재시작 대사 상태를 JSON으로 내보낸다.
- 증거 파일에는 DB 원문·원장 사건·자격정보를 넣지 않고 SHA-256과 감사 사건을 남긴다.

## 11차 — 저장 실험 편향 감사

- 선택 실험과 같은 데이터셋으로 로컬에 저장된 전략 시도 수를 집계한다.
- 선택 실험의 walk-forward 실행 수, OOS fold 수와 OOS 거래 수를 저장 결과에서 집계한다.
- 로컬 카탈로그는 외부·삭제 실험까지 완전하다고 증명할 수 없으므로 데이터 스누핑은 `needs_review`로 유지한다.
- 과거 시점의 종목군 편입·상장폐지 이력이 없으므로 생존편향도 `needs_review`로 유지한다.

## 12차 — 재시작 잠금 UI 일치

- 앱 시작 후 내부 원장 대사가 완료되기 전에는 엔진의 `모의 후보 생성`과 `내부 모의체결 승인` 버튼을 비활성화한다.
- 성과 화면 상단에 잠금 이유와 원장 대사 실행 버튼을 표시한다.
- UI 이벤트 핸들러와 Rust 명령 양쪽에서 잠금을 검사해 우회 호출을 차단한다.

## 검증 경계

- 복구 증거 내보내기는 실제 복원이나 운영 DB 교체가 아니다.
- 로컬 실험 횟수는 완전한 연구 이력이나 편향 통과 판정이 아니다.
- 내부 원장 대사는 KIS·거래소 원격 계좌 대사를 대신하지 않는다.
- 실전 주문 전송은 계속 비활성이다.
