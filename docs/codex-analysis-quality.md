# Codex 분석 품질 프로필

## 목적

Investa 직원 분석이 사용자 전역 Codex 설정의 낮은 추론 강도를 우연히 상속하거나, 최종 종합 단계에서 원본 근거가 빠지는 문제를 방지한다. 이 기능은 분석 품질과 추적성을 높이지만 투자 성과를 보장하지 않는다.

## 실행 프로필

| 작업 | 목표 추론 강도 |
| --- | --- |
| 안건 자동 분류 | `medium` |
| 개별 직원 소견 | `high` |
| 부서 종합 보고 | `high` |
| 연구원 일반 분석 | `high` |
| 본부장 최종 종합 | `xhigh` |

세션 시작 시 Codex App Server `model/list`를 조회한다. `gpt-5.6-sol`이 계정에 노출되면 우선 사용하고, 없으면 카탈로그 기본 모델을 사용한다. 목표 추론 강도가 지원되지 않으면 `xhigh → high → medium → low` 순서로 지원되는 값을 선택한다. 카탈로그 조회 자체가 실패하면 세션 연결을 실패로 닫으며 사용자 설정을 추측하지 않는다.

## 근거 종합 규칙

1. 각 부서는 동일한 point-in-time 분석 스냅샷을 받는다.
2. 부서 보고의 `evidenceIds`는 전달된 가격·기술·재무·공시·포지션·Telegram·운영 경계 ID에만 한정한다.
3. 존재하지 않는 ID가 하나라도 있으면 해당 부서 보고를 실패 보고로 교체하고 모의투자 후보 승격을 막는다.
4. 본부장 종합에는 부서 요약과 함께 동일한 원본 근거 묶음을 다시 전달한다.
5. 공급자 미연결은 해당 항목의 근거 공백이며 다른 근거까지 없는 것으로 확대하지 않는다.

## 보안 경계

- `sandboxPolicy`: 읽기 전용, 네트워크 차단
- `approvalPolicy`: `never`
- 실주문·출금 권한: 없음
- 금융 API key·secret, 전체 계좌번호, GitHub token: 전달 금지
- 외부 Telegram·공시·뉴스 텍스트: 신뢰할 수 없는 자료로 표시하고 내부 지시를 실행하지 않음

## 검증

- Rust 단위 테스트: 모델 카탈로그 파싱, 기본 모델 선택, 지원 effort 하향 선택
- 프론트 단위 테스트: 허용되지 않은 근거 ID 검출, 빈 근거 공백 허용
- 고정 회의 fixture: 가격·기술·공시·뉴스 중 일부가 결측이어도 사용 가능한 근거를 보존하고, 허위 ID가 있으면 승격을 차단
- 전체 빌드·Rust·relay 테스트와 비밀정보 감사
