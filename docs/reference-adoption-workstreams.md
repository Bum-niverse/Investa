# 주요 기능 레퍼런스와 개발 작업군

기준일: 2026-08-25

이 문서는 추가 기능을 `지금 개발`, `Codex 연결`, `계좌·외부 자격정보 연결`, `모델 연구`로 나눈다. 외부 저장소의 성과 수치나 전략을 Investa의 성과로 가져오지 않으며, 새 의존성·모델·계정을 연결하기 전에는 계약과 검증 기준만 준비한다.

## 1. 지금 개발 가능한 범위

### 완료: 백테스트 경험적 부트스트랩

- 저장 백테스트의 완료 거래 손익을 고정 seed로 2,000회 재표집한다.
- 5·50·95 분위 수익률, 손실 확률, 초기자금 50% 이하 도달 확률과 최악 경로 낙폭을 계산한다.
- 완료 거래가 5건 미만이면 수치를 만들지 않는다.
- 독립·동일분포 재표집이라는 한계를 결과에 포함하며 승격이나 주문 권한을 부여하지 않는다.

### 완료: 통화 단위 포트폴리오 위험 분석과 불변 스냅샷

- 동일 시점·동일 통화로 정렬된 종목 수익률과 비중만 받는다.
- 역사적 95% VaR·CVaR, 100개 이상 관측에서 99% VaR, 비중 집중도 HHI, 종목 상관과 사용자 정의 충격 손익을 계산한다.
- 명시적인 시점 정합 환율이 없으면 KRW·USD 같은 서로 다른 통화를 합산하지 않는다.
- 계산 입력과 결과를 동일한 스냅샷 ID로 SQLite에 불변 저장하고 최대 100건을 재조회한다.

### 완료: 전략 보호장치 평가 계약

- 쿨다운, 반복 손절, 연속 손실, 최대 낙폭, 종목별 저수익 보호를 전역 또는 종목 잠금으로 구분한다.
- 현재 시각을 입력으로 받아 동일 기록에서 동일 결과를 만들며 미래·역순 거래 사건은 거절한다.
- 결과의 `liveOrderAllowed`는 항상 `false`다.

### 완료: 운영 경로 연결 1차

- 보호 정책값은 위험정책 백테스트 추천 결과에 포함되고 사용자가 승인한 활성 버전만 적용한다.
- 내부 모의원장의 매수·매도를 평균원가 기준 종료 거래로 재구성해 신규 매수 후보 생성·승인 직전에 평가한다.
- 전역·종목 잠금은 신규 진입만 막고 위험 축소를 위한 매도는 막지 않는다.
- 허용·차단 판정을 SQLite 이력으로 저장한다. 실전 주문 권한은 계속 `false`다.
- 성과 화면에서 보호정책 사용 여부와 관측·잠금·쿨다운 기간, 반복 손절·연속손실·낙폭·종목 손익 기준을 추천안에 포함할 수 있다.

### 완료: 강건성 결과 연구원 UI 노출

- 저장 백테스트를 열면 2,000회 재표집의 5~95% 수익률 범위, 손실 경로 확률과 자본 50% 이하 경로 확률을 표시한다.
- 표본이 부족하거나 이전 형식의 기록이면 수치를 꾸며내지 않고 재실행 안내를 표시한다.

### 남음: 운영 시각화와 고도화

- 매매운영 패널에 전략 보호 판정 이력과 잠금 만료 시각을 직접 표시한다.
- 포트폴리오 위험 입력을 실제 원장 포지션·시점 정합 수익률 시계열에서 자동 구성한다.
- 수동 매도의 종료 사유를 손절·익절·신호·수동으로 구조화해 반복 손절 보호까지 운영 원장에 연결한다.

## 2. Codex 연결 작업

- 유명 저장소·논문 URL을 연구원에게 전달하면 라이선스, commit, 데이터 가정, 전략 규칙과 재현 가능 여부를 구조화한다.
- Codex는 레퍼런스 검토·뉴스/커뮤니티 근거 요약·역할별 소견·기획 초안을 담당할 수 있지만 위험 정책 적용과 주문 권한을 갖지 않는다.
- 모델·전략 제안은 새 불변 실험으로만 저장하고 OOS·비용·편향·부트스트랩 검증 뒤 사용자 검토로 넘긴다.
- Telegram 원격운영은 Bot/Cloud 계정 연결 후 Codex 작업 큐의 입력·결과 회신 채널로 연결한다.

## 3. 계좌·외부 자격정보가 필요한 작업

- KIS 모의계좌: 잔고·보유·주문·취소·체결·재시작 대사의 실제 왕복 검증.
- Toss: 현재 읽기 전용 시세·계좌 조회의 장시간 제한·오류·세션 만료 검증. 실주문은 별도 결정 전 금지.
- Upbit/Binance: 읽기 전용 잔고·포지션 검증, 상품 규격·수수료·펀딩·증거금 관측. 출금 권한은 금지.
- Telegram Bot/Google Cloud: allowlist, webhook 또는 polling, relay 인증, Secret Manager, rate limit·예산 상한과 결과 회신.

계정이 없다는 이유로 연결 성공을 꾸며내지 않는다. 자격정보는 Windows 자격 증명 관리자 또는 Cloud Secret Manager에만 보관한다.

## 4. 모델 연구 작업

### 후보 A: Amazon Chronos-2 / Chronos-Bolt

- 공식 저장소: https://github.com/amazon-science/chronos-forecasting
- 공식 Hugging Face 모델 카드: https://huggingface.co/amazon/chronos-bolt-base
- Apache-2.0. 분위수 시계열 예측과 zero-shot 기준선 후보로 검토한다.

### 후보 B: Google TimesFM 2.5

- 공식 저장소: https://github.com/google-research/timesfm
- Apache-2.0. point forecast와 quantile forecast를 제공하는 시계열 기준선 후보로 검토한다.

두 모델 모두 Python, PyTorch/JAX와 모델 가중치가 필요하므로 이번 묶음에서는 설치하지 않는다. 공통 어댑터는 `modelId`, `modelVersion`, `datasetId`, `assetContractId`, `asOf`, `horizon`, quantile 배열, 실행 환경과 seed를 요구한다. 주식·선물·코인별로 별도 보정하고 순진 기준선과 OOS에서 이기지 못하면 승격하지 않는다.

## 5. 적용한 유명 레퍼런스

- QuantConnect LEAN(Apache-2.0): 모듈형 엔진, 포트폴리오 통계와 최대낙폭·VaR의 독립 위험 분석 관점을 참고했다.
  - https://github.com/QuantConnect/Lean
- Microsoft Qlib(MIT): 데이터·학습·워크플로·기록·포트폴리오 분석을 느슨하게 분리하는 구조를 참고했다.
  - https://github.com/microsoft/qlib
- Freqtrade(GPL-3.0): dry-run, lookahead/recursive analysis와 쿨다운·손절·낙폭 보호 개념만 참고했다. GPL 코드를 복사하거나 링크하지 않았다.
  - https://github.com/freqtrade/freqtrade
- NautilusTrader: backtest·sandbox·live가 같은 도메인 계약을 쓰고 위험·실행·대사를 분리하는 구조를 참고했다. 코드·의존성은 가져오지 않았다.
  - https://github.com/nautechsystems/nautilus_trader

이번 구현은 위 저장소의 코드를 복사하지 않고 Investa의 Rust 타입, 고정소수점, point-in-time 검사와 실전 잠금 경계에 맞춰 독립 작성했다.

## 6. 백테스트 해석 경계

- 부트스트랩 결과는 거래 표본 내부 불확실성만 설명한다. 시장 구조 변화, 거래 불가능, 유동성 고갈과 데이터 오류를 모형화하지 않는다.
- 역사적 VaR·CVaR는 과거 분포가 반복된다는 가정에 의존하며 손실 상한이 아니다.
- 보호장치가 손실을 줄이더라도 수익률을 높인다고 가정하지 않는다. 보호 정책 후보별로 원본과 동일 데이터·비용·기간의 OOS 비교가 필요하다.
- Chronos·TimesFM의 공개 벤치마크 성능은 금융 종목 방향 예측 성능이 아니다. Investa 데이터로 별도 평가하기 전에는 모델 미연결 상태를 유지한다.
