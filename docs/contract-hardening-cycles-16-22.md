# 계약 강화 16~22차 개발 사이클

## 범위

외부 계정·신규 라이브러리·유료 공급자·실주문을 제외하고, 남아 있던 기능명세 중 코드로 검증 가능한 안전 계약을 일곱 묶음으로 보강했다. 숫자를 줄이기 위한 완료 처리는 하지 않고 수용 기준과 테스트가 연결된 항목만 완료로 갱신한다.

## 16차 — ProjectStudio 상태 재감사

- 상위 분류, 직원 역할 노드와 실제 구현 기능을 구분했다.
- 자식 일부가 완료됐다는 이유로 상위 분류를 완료 처리하지 않는다.
- 기능 상태는 해당 노드의 모든 수용 기준이 충족된 경우에만 `done`으로 바꾼다.

## 17차 — 역할별 근거 계약

- 각 역할 근거에 중복 없는 `evidenceId`, 출처, 선택적 리비전과 관측 시각을 요구한다.
- 역할 범위, 관점과 근거 충족도 계약은 기존과 동일하게 서버에서 재검증한다.
- 근거 ID 형식·중복·개수·텍스트 길이가 잘못되면 보고를 거부한다.

## 18차 — 반대 근거와 부서 종합 추적

- 역할 근거와 직원별 부서 소견에 `counterevidence`를 추가했다.
- 부서 종합은 직원별 `evidenceIds`를 유지하며, 근거가 없으면 `evidenceGap`을 반드시 남긴다.
- 분석 보관소에서 근거 ID·리비전·반대 근거를 함께 확인한다.

## 19차 — 대체 데이터 출처 통제

- 필수 출처와 대체 출처, 기준 시각, 리비전, 값 차이와 대체 사유를 기록한다.
- 필수 출처가 없거나 오래돼 대체 출처를 사용한 결과는 분석에만 사용할 수 있다.
- 대체 출처 결과는 주문 승격을 허용하지 않으며 대체 출처도 오래되면 분석까지 차단한다.

## 20차 — 코인 파생 승격 스트레스

- OOS 최소 거래 수, 비용 차감 기대손익, Profit Factor와 MDD를 함께 검사한다.
- 청산 0회, 불리한 펀딩비, 변동성 충격, API 지연 복구와 재시작 대사를 모두 요구한다.
- 통과해도 섀도우 검토 자격만 제공하며 `liveOrderEnabled`는 항상 `false`다.

## 21차 — 통화별 성과와 판단 품질

- KRW·USD·USDT 성과를 통화별로 분리하고 실현·미실현, 총손익·비용·순손익을 따로 계산한다.
- 시점 정합 환율이 없으면 기준통화 합계를 만들지 않는다.
- 직원·전략 평가는 단순 적중률 대신 Brier 보정 오차, 양의 기대값 건수와 실현 순손익을 기록한다.

## 22차 — 패널 접근성과 전체 검증

- 에이전트 상세 패널이 닫혀 있을 때 내부 컨트롤을 키보드 탐색에서 제외한다.
- `Escape`로 닫고 선택했던 에이전트 버튼으로 포커스를 되돌린다.
- 프론트엔드 프로덕션 빌드와 전체 Rust 단위 테스트를 실행한다.

## 검증 결과

- `pnpm run build`: 통과
- `cargo test --manifest-path src-tauri/Cargo.toml`: 167 통과, 4 제외
