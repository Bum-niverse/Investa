# Investa 백엔드 개발 로드맵

## 목표

픽셀 사옥 UI의 로컬 시뮬레이션을 실제 데이터·분석·모의주문 상태와 연결한다. LLM은 분석 근거와 거래 계획만 만들고 자격증명, 주문 전송과 위험 정책 실행에는 접근하지 않는다. 최초 운영 범위는 국내·미국 주식의 섀도우 실행과 KIS 모의투자이며, 코인 현물·파생은 주식 모의운영이 안정된 뒤 별도 어댑터와 위험 예산으로 추가한다.

현재 연구원 구조화 output, 토스·업비트 일봉 탐색 백테스트, SQLite 불변 연구·회의 기록, KRW/USD append-only 모의계좌, 토스 계좌·보유자산 읽기, KIS 모의 잔고·사용자 확인형 국내 모의주문·취소·체결조회, 소수 코인 수동 모의체결, 부서별 Codex 오케스트레이션, 승인형 주문 후보, 최신 토스·업비트 봉 기반 섀도우 감시와 회의 복구를 구현했다. 실전 주문 전송 코드는 없다. 위험 정책은 OHLC 손절·익절·일일손실 재백테스트 → 추천 저장 → 사용자 승인 후 주문 금액·MDD·당일 실현손실 게이트에 적용한다.

## 구현 원칙

- Tauri Rust 계층이 파일, SQLite, 비밀정보, 백그라운드 작업과 외부 API를 소유한다.
- React 렌더러는 검증된 DTO와 이벤트만 받고 API 키나 브로커 원문 응답을 보관하지 않는다.
- 시장 데이터는 `eventTime`, `availableAt`, `source`, `ingestedAt`을 기록하고 원천과 정규화 결과를 분리한다.
- 중복 주문, 잘못된 수량·가격, 오래된 시세, 연결·원장 불일치와 킬 스위치는 초기부터 제거할 수 없는 최소 안전 커널로 유지한다.
- 손절·익절, 포지션 비중, 변동성 조절, 레버리지와 손실 한도는 연구원이 여러 정책 후보를 백테스트하되 사용자가 정한 절대 상한을 넘지 못한다.
- 주문은 AI 응답을 직접 실행하지 않고 구조화 거래 계획 → 최소 안전 커널 → 브로커 어댑터 순서로만 전달한다.
- 실전 주문은 MVP에서 비활성화하고, 모든 개발은 섀도우 → KIS 모의투자 순서로 검증한다.
- 외부 API와 SQLite 라이브러리는 도입 전에 라이선스, 비용, 유지보수성과 대안을 확인하고 승인받는다.

## 개발 순서

### 0. 기반과 테스트 하네스

- `App.tsx`에 모인 조직 데이터, UI 상태와 업무 시뮬레이션을 도메인·서비스·표시 계층으로 분리한다.
- Rust command의 요청·응답 DTO, 오류 코드, 이벤트 envelope와 시간·통화·수량 단위를 정의한다.
- 프론트 단위 테스트, Rust 단위·통합 테스트, 임시 SQLite 테스트 DB와 공식 검증 명령을 추가한다.
- 개발·테스트·모의·실전 환경을 분리하고 실전은 컴파일·설정 양쪽에서 기본 잠금한다.

완료 조건: 빈 데이터, 잘못된 입력, 재시작과 실패 응답을 자동 검사하며 현재 UI 빌드가 유지된다.

### 0.5. Codex App Server 연결

상태: 핵심 연결 완료. 별도 CLI 설치, ChatGPT 로그인 확인, stdio handshake, 직원별 읽기 전용 thread, 실제 응답 delta·완료·오류·취소 UI, 사용 한도 표시와 thread 영속화, 본부장 안건 자동 분류·선택 부서 보고·최종 종합을 구현했다. 남은 작업은 장시간 회의 검수와 한도·복구 UX 보강이다.

- 실행 가능한 Codex CLI 경로 선택·탐지, 버전·로그인·app-server handshake 진단을 구현한다.
- Tauri Rust가 `codex app-server`를 stdio JSONL 자식 프로세스로 실행하고 종료·비정상 종료·재시작을 관리한다.
- ChatGPT browser/device-code 로그인, 계정·planType·사용 한도와 오류 상태를 표시한다.
- 역할별 thread, 구조화 output schema, delta·완료·오류·취소 이벤트를 UI 업무 상태에 연결한다.
- 연구원은 읽기 전용·네트워크 OFF로 시작하고 레퍼런스 수집 네트워크는 목적지 제한과 승인 후 별도 개방한다.

완료 조건: 가짜 연구 요청을 Codex에 보내 실제 스트리밍 응답과 작업 상태를 UI에 표시하며 토스증권 자격증명·주문 도구에는 접근하지 못한다.

### 1. 첫 수직 기능: 연구원 레퍼런스 분석

- 사용자가 GitHub 레포·논문 URL, 분석 목적, 대상 시장·종목과 비교 조건을 연구원에게 지시한다.
- URL, 저장소, commit, 라이선스, 전략 설명, 필요 데이터, 실행 환경과 주장 성과를 근거 ID와 함께 저장한다.
- 임의 코드를 바로 실행하지 않고 매수·매도·관망 조건, 피처, 비용 가정, 포지션 규칙과 알려지지 않은 항목을 공통 `StrategySpec` 후보로 추출한다.
- 레포의 주장 성과와 Investa가 재현한 성과를 분리하고 실행 불가·라이선스 제한·정보 부족도 결과로 보고한다.
- Tauri 이벤트로 연구원의 실제 분석 단계와 결과를 현재 픽셀 UI에 연결한다.

완료 조건: 외부 주문 없이 한 레포를 `접수 → 근거 수집 → 전략 명세 후보 → 검토 보고서 → UI 표시`로 재현한다.

### 2. 시점 정합 시장 데이터

- 국내·미국 종목, 거래소, 통화, 거래일과 시간대 canonical schema를 만든다.
- 가격·거래량부터 수집하고 재무·공시·뉴스·환율·수급은 공급자별 어댑터로 확장한다.
- 중복, 결측, 지연, 정정, 장 마감과 휴장 상태를 품질 플래그로 기록한다.
- 동일 종목·시각 중복과 다대다 병합을 차단하고 미래 정보 누수를 검사한다.
- 캐시, 호출 제한, 타임아웃, 재시도와 공급자 장애 시 fail-closed 정책을 구현한다.

완료 조건: 특정 판단 시각에 실제로 이용 가능했던 데이터만 snapshot ID로 다시 읽을 수 있다.

### 3. 전략 플러그인·지표·피처

- 연구원이 만든 `StrategySpec`을 허용된 지표·연산·주문 신호만 사용하는 실행 가능한 전략 플러그인으로 변환한다.
- 외부 레포 코드는 기본적으로 직접 실행하지 않고, 꼭 필요한 경우 고정 commit·라이선스 검토·격리 환경·네트워크와 자격증명 차단을 요구한다.
- 기술 지표, 변동성, 거래량, 재무비율과 시장 레짐 계산을 순수 함수로 구현한다.
- 계산 입력·파라미터·코드 버전·출력 schema를 기록한다.
- 관심 종목 전체에 LLM을 호출하지 않고 결정론적 필터로 후보를 먼저 줄인다.
- NaN, 0 거래량, 상장 초기, 액면분할과 통화 단위 경계를 테스트한다.

완료 조건: 같은 레포 commit, `StrategySpec`, snapshot과 설정은 항상 같은 신호·후보·피처 결과를 만든다.

### 4. 백테스트와 연구실

상태: 저장 실험 복제·재실행과 고정 파라미터 시간순 OOS 반복 검증 3차 완료. 기존 OOS·PBO·MinTRL·기준선·레짐 검사에 완료 거래 손익의 고정 seed 2,000회 경험적 부트스트랩을 추가했다. 거래 5건 미만이면 수치를 만들지 않고, 충분한 경우 5·50·95 분위 수익률, 손실 확률, 초기자금 50% 이하 도달 확률과 최악 경로 낙폭을 결과에 저장한다. 이는 시장 레짐 변화를 재현하지 않는 민감도 검사이며 자동 승격 기준이 아니다. 적용·보류한 논문과 공식 문서 근거는 `development-reference-policy.md`에 기록한다.

- 시간순 분할, walk-forward, OOS 구간과 기준 전략 비교를 구현한다.
- 수수료·세금·슬리피지·환율을 포함하고 survivorship/look-ahead/data-snooping 검사를 기록한다.
- 승률 외 기대값, Profit Factor, MDD, 거래 수, 레짐별 안정성과 민감도를 계산한다.
- 전략·데이터·파라미터·비용 모델 버전을 불변 실험 기록으로 저장한다.

완료 조건: 55% 승률은 단독 합격 조건이 아니며 프로젝트에 정의된 전체 승격 기준을 자동 판정한다.

### 5. 멀티에이전트 분석 오케스트레이터

현재 기반 정책: 일반 안건 최대 5회, 중요 안건 최대 9회, 동시 2명, Codex 사용량 80% 또는 사용량 확인 실패 시 새 안건 중단. 호출 예산에는 본부장 자동 분류 1회와 최종 종합 1회가 포함되며, 일반 안건은 관련 부서 최대 3개, 중요 안건은 최대 7개를 구조화 응답으로 실행한다. 주식·코인·주문·레버리지·시스템 변경·외부 발행 플래그에 따라 필수 안전 부서를 Rust가 보강하고, 실행·복합 안건은 중요 안건으로 자동 상향한다. 다음 단계는 실제 App Server 장시간 수동 검수와 실패·취소 UX 보강이다.

- 역할별 입력·출력 JSON schema, 근거 ID, 신뢰도, 반대 근거와 무효화 조건을 정의한다.
- Codex App Server 연결은 별도 어댑터로 격리하고 인증 세션과 사용 한도를 UI에 노출한다.
- 도구 허용 목록, 최대 입력·출력, 타임아웃, 취소, 재시도와 비용·사용량 한도를 적용한다.
- 에이전트 응답을 schema 검증한 뒤에만 다음 역할로 넘기고 실패는 관망으로 귀결한다.
- UI 퍼센트는 타이머가 아니라 실제 작업 이벤트와 완료된 단계 수로 계산한다.

완료 조건: 에이전트 하나가 실패하거나 잘못된 JSON을 반환해도 주문 후보가 생성되지 않고 원인을 재현할 수 있다.

### 6. 연구 전략 섀도우 실행과 최소 안전 커널

상태: 국내주식·코인 현물 수직 기능 완료. 감시 주기마다 토스 또는 업비트 최신 200개 완료 일봉을 다시 받아 신호를 계산하고 후보만 생성한다. 코인 수량은 1억분의 1 고정소수점으로 원장에 기록하며 재시작 복구·중지·오류 상태를 보존한다.

- 매수·매도·관망, 진입가, 손절가, 목표가, 보유 기간, 주문 유형, 수량 제안과 무효화 조건 schema를 만든다.
- 백테스트를 통과한 전략만 append-only 섀도우 원장에 연결하고 Tauri 이벤트로 실제 진행 단계·신호·가상 체결을 표시한다.
- 이 단계에서는 중복 주문, 잘못된 수량·가격, 오래된 시세, 연결·원장 불일치와 킬 스위치만 제거할 수 없는 최소 안전 커널로 검사한다.
- 연구원이 제안한 조정 가능한 위험 정책은 버전만 기록하고 아직 자동 적용하지 않는다.

완료 조건: 레포 근거부터 전략 명세·백테스트·섀도우 사건까지 하나의 추적 ID로 재생되며 최소 안전 규칙 실패 시 가상 주문도 생성되지 않는다.

### 7. 주문 상태 머신과 불변 원장

상태: KRW·USD 내부 즉시체결과 로컬 지정가 대기·취소 범위 완료. 안전 승인·사용자 승인·제출·부분체결·체결·취소·기각·만료의 허용 전이를 정의하고 후보 사건과 계좌 체결 사건을 분리 저장한다. 현재 시장가 원장은 전량 즉시체결만 생성하고 지정가는 KIS 연결 전 로컬 대기 상태로만 저장하므로 부분체결·정정·원격 주문 취소는 향후 KIS 모의 어댑터 연결 때 추가 검증한다.

- 주문 생성·검증·전송·접수·부분체결·체결·취소·거절 상태와 허용 전이를 정의한다.
- idempotency key와 브로커 주문 ID를 분리하고 중복 전송을 차단한다.
- 주문·체결·수수료·세금·환율·정정 사건을 append-only로 저장한다.
- 포지션, 현금과 손익을 원장 재생으로 다시 계산할 수 있게 한다.

완료 조건: 중복 응답, 부분체결, 순서가 뒤바뀐 이벤트와 비정상 종료를 자동 테스트한다.

### 8. KIS 읽기 전용 연결과 모의투자

상태: 코드 준비 완료·외부 검증 보류. 모의 App Key·Secret, HTS ID, 계좌번호와 상품코드의 형식 검증·Windows 자격 증명 관리자 저장·삭제, 모의 도메인 토큰·HashKey 발급, 국내주식 잔고·보유종목 조회, 명시적 확인형 주문·취소와 당일 체결 조회까지 구현했다. 사용자가 한국투자증권 계좌 개설과 모의계좌 연결을 나중에 진행하기로 결정했으므로 실제 모의 서버 검증·자동 내부 원장 반영·원격 대사는 보류한다. 실전 주문 경로는 계속 잠겨 있다.

- 자격증명은 OS 보안 저장소에서만 읽고 DB·렌더러·로그·내보내기에 기록하지 않는다.
- 먼저 토큰·시세·잔고·미체결 조회만 연결하고 주문 권한 진단은 주문 없이 수행한다.
- 국내·미국 시장 규칙, 호가 단위, 거래 시간, 통화, 세금과 주문 유형을 어댑터로 분리한다.
- 모의주문 전송은 위험 게이트 결과와 원장 idempotency key가 있을 때만 허용한다.
- 공급자 rate limit, 토큰 만료, 점검, 네트워크 단절과 오류 원문 마스킹을 처리한다.

완료 조건: 실전 계좌와 실전 주문 경로는 계속 비활성화된 상태에서 KIS 모의계좌 조회·주문·취소를 재현한다.

### 9. 재시작 대사와 운영 복구

상태: 회의 작업 복구와 내부 엔진 주문 대사 2차 완료. 진행 단계·선택 부서·보고·종합을 체크포인트로 저장하고 비정상 종료 시 중단 기록을 처음부터 재실행하거나 닫을 수 있다. 앱 재시작 시 통합 엔진 후보 생성·승인을 백엔드와 UI 양쪽에서 잠그고, 내부 원장 대사 불일치가 0건일 때만 다시 연다. SQLite·KRW/USD 원장 자동점검, 감사 JSON 내보내기, 백업 복원 사전검사, 운영 DB를 교체하지 않는 격리 복구 훈련, 검증 백업 목록과 민감 원문 없는 복구 증거 내보내기를 구현했다. 실제 DB 교체 복원과 KIS 원격 대사는 아직 미구현이다.

- 시작 시 신규 주문을 잠그고 KIS 잔고·미체결·체결과 내부 원장을 대조한다.
- 누락·중복·수량·가격 불일치를 자동 수정하지 않고 차이와 제안 조치를 표시한다.
- 사용자가 대사를 확인한 뒤에만 자동매매 감시를 재개한다.
- 데이터 지연, 브로커 장애, 손실 한도와 킬 스위치 사건을 알림·감사 로그에 남긴다.

완료 조건: 주문 중 강제 종료 후 재시작해도 중복 주문 없이 같은 포지션으로 복구한다.

### 10. 포트폴리오·성과·운영 화면 연결

상태: 좌측 통합 모의투자 터미널과 별도 원장·성과 화면 1차, 백엔드 포트폴리오 위험 분석과 불변 스냅샷 저장·조회 1차 완료. 동일 통화·동일 시점으로 정렬된 수익률만 받아 역사적 95% VaR·CVaR, 충분한 표본의 99% VaR, 집중도 HHI, 상관과 명시적 스트레스 충격을 계산한다. 혼합 통화는 시점 정합 환율 없이 합산하지 않는다. UI 연결과 내부 원장 포지션의 수익률 시계열 자동 생성은 후속 범위다.

- 계좌, 현금, 포지션, 노출, 실현·미실현 손익과 MDD projection을 제공한다.
- 승률, 기대값, Profit Factor와 비용을 시장·전략·기간별로 계산한다.
- 현재 픽셀 직원 상태는 백엔드 job·event·error ID와 연결하고 상세 패널에서 근거를 조회한다.
- 빈 상태, 오래된 데이터, 부분 실패, 오프라인과 복구 중 상태를 구분한다.

완료 조건: UI의 모든 진행률·분석 결과·주문 상태가 저장된 백엔드 사건으로 추적된다.

### 11. 연구원 기반 위험관리 정책 연구와 적용

상태: 정책 버전 저장·추천/활성 상태 분리와 사용자 승인, 전략 보호 평가 및 운영 연결 1차를 구현했다. 저장 OHLC 손절·익절·일일손실에 더해 쿨다운, 반복 손절, 연속 손실, 최대 낙폭과 종목별 저수익을 연구 백테스트에서 평가한다. 성과 화면에서 선택형 보호 기준을 추천안에 포함할 수 있다. 활성 정책은 내부 모의원장의 실제 매수·매도 사건으로 종료 거래 손익을 재구성해 수동·섀도우·통합 엔진의 신규 매수 후보 생성·승인 직전에 다시 검사하며 허용·차단 판정을 SQLite에 저장한다. 매도는 위험 축소 행동이라 잠그지 않고 실전 주문 권한은 계속 비활성화한다. 남은 작업은 운영 UI 이력, 종료 사유 구조화와 잠금 해제 알림이다.

- 연구원은 전략별 손절·익절, 포지션 비중, 현금 비중, 변동성 조절, 동시 보유 수, 쿨다운, 일일 손실 한도와 레버리지 후보를 조합한다.
- 각 정책을 시간순 OOS, walk-forward, 폭락·급등·거래정지·API 지연 스트레스 시나리오로 백테스트한다.
- 수익률뿐 아니라 MDD, 손익비, 기대값, 연속 손실, 회복 기간과 파산 위험의 Pareto 비교를 보고한다.
- 사용자가 정한 절대 상한과 최소 안전 커널은 연구원·LLM·전략 플러그인이 변경할 수 없다.
- 사용자가 선택한 정책 버전만 섀도우와 모의투자에 승격하며 변경 이력과 롤백 버전을 보존한다.

완료 조건: 동일 전략에 보수·중립·공격 정책을 재현해 비교하고 선택된 정책이 절대 안전 상한 안에서만 적용된다.

### 12. 업비트 코인 현물·파생 sandbox

상태: 공개 원화마켓 현재가·일봉·1분봉과 내부 KRW 원장 시장가 체결, 로컬 지정가 대기·취소를 구현했다. 개인 API 키, 거래소 잔고, 원격 주문·취소, 소수 코인 수량과 파생상품은 미구현이며 출금 경로는 계속 금지한다.

- 국내 원화 현물의 첫 거래소 어댑터는 업비트 Open API로 구현한다. 공개 시세와 개인 잔고·주문 경계를 분리하고, 비밀키는 Rust와 OS 보안 저장소 밖으로 내보내지 않는다.
- 내부 섀도우 체결 → 업비트 주문 생성 테스트 → 사용자 승인형 현물 주문 순으로 승격한다. 출금 API는 구현·허용하지 않는다.
- 케이뱅크는 사용자가 업비트에 연결한 원화 입출금 계좌일 뿐 Investa가 직접 제어하는 주문 API가 아니다. 별도 케이뱅크 API 연결을 자동매매 전제 조건으로 두지 않는다.
- 주식 계좌와 별도 DB 논리 구획, 위험 예산, 스케줄러와 거래소 어댑터를 사용한다.
- 현물부터 검증한 뒤 무기한 선물은 별도 거래소 sandbox에서 격리증거금·최대 2배·reduce-only로 제한한다.
- mark price, 청산가, 유지증거금, 펀딩비, 거래소 지연과 24시간 대사를 추가한다.

완료 조건: 업비트 현물은 내부 원장과 주문 생성 테스트를 재현하고 사용자 승인 없이는 실제 주문을 전송하지 않는다. 주식 모의운영과 현물 안정화 전에는 코인 파생 주문 경로를 활성화하지 않는다.

### 13. 국내 주식선물·지수선물 sandbox

상태: 내부 모의 수직 기능 1차 완료. `모의 → 선물`에서 사용자가 명시한 상품 구분·가격·계약승수·개시/유지증거금률·수수료 가정으로만 롱·숏 포지션을 개설하고, 가용현금·예약증거금·미실현/실현손익·유지증거금 미달 경고를 계산한다. 개설·시가평가·청산은 SQLite append-only 사건으로 저장하고 재시작 시 재생한다. 실제 KRX 상품 규격·시세, 만기·롤오버, 일일정산, KIS `03` 모의계좌와 외부 주문은 아직 연결하지 않는다.

- 공식 상품 마스터와 거래일·만기월·최종거래일을 읽기 전용으로 정규화한다.
- 일일정산, 변동증거금, 가격제한폭과 만기·롤오버 사건을 추가한다.
- 실제 상품별 증거금률은 거래소·증권사 관측값과 적용 시각을 기록하고 임의 기본값을 사용하지 않는다.
- 내부 sandbox 회귀 검증 후에만 KIS 국내선물옵션 모의계좌 `03` 어댑터를 별도 연결한다.

완료 조건: 계좌 없이 계약 전체 생명주기와 재시작 원장 재생을 검증하고, 증권사 연결 후에도 사용자 승인 없이는 외부 모의주문을 보내지 않는다.

## 바로 시작할 작업

1. 실행 가능한 Codex CLI 경로 선택·버전·로그인 진단
2. Rust `codex app-server` stdio 프로세스·JSON-RPC handshake
3. 계정·planType·사용 한도와 연결 오류 DTO
4. 역할 thread·turn·stream·cancel을 가짜 연구 요청으로 검증
5. 완료: 연구 요청, 레퍼런스, 근거와 `StrategySpec` 도메인 타입·검증
6. 완료: point-in-time 고정 데이터와 첫 결정론적 백테스트·비용 계산
7. 완료: append-only 인터페이스와 인메모리 모의계좌 원장 재생
8. Codex 연구 작업 output schema와 실제 진행 이벤트를 연구원 패널에 연결
9. 완료: SQLite 라이브러리 선택 ADR, 연구·데이터셋·백테스트 불변 저장과 조회 UI

첫 단계에서는 KIS, 유료 데이터 공급자와 외부 레포의 임의 코드를 연결하거나 실행하지 않는다. Codex 연동 전에는 고정 fixture로 연구 요청·전략 명세·보고서 계약을 검증한다.

Codex·토스증권·티스토리의 인증 방식과 적용 시점은 [외부 연동 우선순위](external-integration-roadmap.md)에 별도로 기록한다.

## 14. Telegram 원격운영

상태: 계정 비의존 로컬 코어 완료, 외부 연결 보류. 허용 사용자, 명령 분류, 입력 제한, 24시간 replay window, 멱등 요청, SQLite 작업·사건 원장과 로컬 승인 상태 머신을 구현했다. 분석·회의는 큐에 등록하지만 투자·자동매매·시스템 제어는 로컬 승인 대기로만 저장하며 실전 주문은 계속 잠근다.

후속 작업은 Telegram Bot 송수신, Google Cloud relay 인증·비용 상한, local Codex/Gemini 공급자 선택, 결과 회신과 실패 복구다. 계정과 token이 준비되기 전에는 외부 연결을 완료로 표시하지 않는다. 세부 계약은 [Telegram 원격운영 엔진](telegram-remote-control-engine.md)에 정리했다.
