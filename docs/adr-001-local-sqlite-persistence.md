# ADR-001: 로컬 연구 기록에 SQLite 사용

- 상태: 채택
- 기준일: 2026-08-21

## 배경

연구 보고서, 시점 정합 가격봉과 백테스트 결과가 메모리에만 있어 앱 재시작 후 재현할 수 없었다. Windows 로컬 우선 Tauri 프로그램이므로 별도 서버 없이 트랜잭션, 중복 방지, 조회와 무결성 검사가 필요하다.

## 결정

Rust 계층에서 `rusqlite 0.40.2`(MIT)와 `bundled`, `fallible_uint` 기능을 사용한다. 앱 데이터 폴더의 단일 SQLite 파일을 Rust `Mutex<Connection>`으로 소유하고 React에는 제한된 읽기 DTO만 노출한다.

- `bundled`: Windows의 시스템 SQLite 설치·버전에 의존하지 않는다.
- `fallible_uint`: 시간·수량의 `u64`를 SQLite 정수 범위 안에서 실패 가능 변환한다.
- WAL·foreign key·`STRICT` 테이블·busy timeout·`quick_check`를 적용한다.
- 확장 로딩, SQLCipher, 네트워크 DB와 ORM은 사용하지 않는다.
- 연구 보고서·dataset·실험 결과는 한 트랜잭션으로 저장하고 기존 불변 ID를 덮어쓰지 않는다.
- 토스증권 Client ID·Secret, Codex 토큰과 계좌 정보는 저장하지 않는다.

## 대안

- JSON 파일: 간단하지만 원자적 다중 레코드 저장, 유일성·외래키와 동시 접근 검사가 약하다.
- 서버 DB: 다중 기기에는 유리하지만 현재 로컬 우선·단일 사용자 범위에 운영 복잡성과 공격 표면이 과하다.
- Tauri SQL 플러그인: React에서 SQL 접근 경계를 만들 가능성이 있어 Rust 도메인 계층이 저장소를 소유한다는 원칙과 맞지 않는다.

## 결과

배포 파일 크기와 Rust 빌드 시간은 소폭 늘지만 Windows 환경 재현성이 좋아진다. 현재 파일 자체 암호화는 제공하지 않으므로 개인정보와 자격증명은 저장 대상에서 제외한다. 향후 실제 계좌 데이터가 범위에 들어오면 별도 암호화·보존·백업 결정을 다시 기록한다.
