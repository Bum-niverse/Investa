# 전략 판단·실행 주기 계약

기준일: 2026-08-30

## 목적

자동매매 전략의 **판단 주기**와 체결 상태를 확인하는 **실행 관리 주기**를 분리한다. 현재 네 가지 전략 플러그인은 완료 봉 기반이므로 `tick` 판단을 지원한다고 표시하지 않는다. 모든 결과는 연구·내부 섀도우 전용이며 외부 실주문 권한을 만들지 않는다.

## 변경 전 보안 사전검토

- 보호 자산: 버전형 `StrategySpec`, 백테스트 결과와 운용 주기의 일치성, 완료 봉의 시점 정합성, 내부 섀도우 잠금.
- 신뢰 경계: React/Tauri IPC 외부 입력 → Rust 계약 검증 → 저장된 실험·런타임. 클라이언트가 공급자 지원 여부나 실주문 가능 여부를 결정하지 않는다.
- 주요 위험: 임의 문자열·범위 초과 초 입력, 봉 전략의 틱 지원 과장, 백테스트·런타임 interval 불일치, 미완료 봉 사용, 판단·실행 주기 혼동, 기능 추가를 통한 실주문 경계 우회.
- 통제: 닫힌 Rust enum, 고정된 9개 판단 주기, `1..=86,400`초 실행 관리 범위, 완료 봉 전략의 `tick` 거부, 백테스트·런타임·판단 주기 완전 일치, `liveOrderAllowed=false` 강제.
- 외부 영향: 신규 네트워크 호출, 자격정보, DB 마이그레이션, 계좌·주문·출금 권한 변경이 없다.
- 차단 여부: 치명적 보안 문제를 발견하지 않았다. 위 통제를 테스트하는 조건으로 구현을 진행한다.

## 계약

판단 주기는 다음 9개로 고정한다.

- `tick`
- `1m`, `3m`, `5m`, `15m`, `30m`
- `1h`, `4h`, `1d`

실행 관리 주기는 다음 중 하나다.

- `tick`: 시장 사건마다 내부 상태를 확인한다.
- `fixedSeconds`: 현재 섀도우 감시 저장 계약과 같은 15초 이상 86,400초 이하의 고정 주기로 내부 상태를 확인한다.

현재 이동평균 교차·가격 채널 돌파·평균 이격 회귀·ATR 변동성 확장 플러그인은 완료 봉 기반이다. 따라서 `1m`부터 `1d`까지만 판단할 수 있고 `tick` 판단 요청은 명시적 사유와 함께 거부한다. 봉 판단 주기는 백테스트 interval 및 런타임 interval과 모두 정확히 일치해야 한다.

## 완료 조건

- 9개 판단 주기가 직렬화 가능한 닫힌 계약으로 노출된다.
- 완료 봉 전략이 `tick` 판단을 거부한다.
- 판단 주기와 실행 관리 주기를 독립적으로 선택할 수 있다.
- 백테스트·런타임 interval 누락 또는 불일치를 거부한다.
- 잘못된 고정 초 범위와 필요한 PIT 봉 필드 누락을 거부한다.
- 성공 결과에도 외부 실주문은 항상 잠겨 있다.
