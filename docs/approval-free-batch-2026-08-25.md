# 승인 불필요 기능 묶음 개발

기준일: 2026-08-25

## 이번 묶음에서 완료한 기능

- 워크스페이스 시작 시 재시작 대사 잠금과 체크포인트 복구 상태를 유지한다.
- KST·ET·UTC 표시 시간대, 데이터 만료 기준과 경고 등급을 로컬 SQLite에 저장한다.
- 국내주식·미국주식·코인·선물 주문의 통화, 호가, 수량 단위와 고정소수점 명목 금액을 결정론적으로 정규화한다.
- 조회 요청의 429·5xx·timeout을 제한 횟수 지수 백오프로 분류하고 변경 요청은 자동 재시도하지 않는다.
- 뉴스 사실, 커뮤니티 심리와 확산량을 원천 리비전·가용 시각 기준으로 분리하며 미래 자료와 중복을 제외한다.
- 직원 패널에 역할·작업·근거·대화 빠른 이동을 추가하고 Escape·포커스 복귀 동작을 유지한다.
- 모의 체결 원장에 선택적 청산 사유와 원인 사건 ID 필드를 추가했다. 기존 매도는 수동으로 호환하며 반복 손절은 명시적 `stop_loss`만 집계한다.
- 저장 내부 원장 포지션과 저장 가격 데이터의 공통 시점을 이용해 KRW·USD별 포트폴리오 위험 입력을 구성하고 불변 스냅샷으로 저장한다. 환율 없이 통화를 합산하지 않는다.
- 전략 보호 판정의 허용·차단 이유와 잠금 만료, 운영 지표의 집계·원천 관측 시각을 성과 화면에서 확인한다.
- 홍보부 근거 묶음·개발기 초안·미디어 검수 계약을 Tauri 명령으로 연결하고 대표 승인된 원고만 앱 데이터 폴더에 수동 게시 패키지로 내보낸다. 외부 자동 게시를 수행하지 않는다.
- 장시간 섀도우 검사 표본에서 후보 중복, 공급자 장애, 메모리·타이머·SQLite 증가량을 검사하는 결정론적 감사기를 추가했다.
- 모의원장을 시점 정합 시세로 재생해 거래당·일일 손실, MDD, 연속 손실과 종목·섹터·시장 노출을 계산하고 계속·축소·중단 권고를 반환한다.
- 거래품질 감시는 가격 불리함과 수수료·세금·환전·펀딩 비용을 분리하고 중복·과다 수량·부분체결·지연을 신규 주문 중지 후보 사유로 기록한다.
- 코인 레버리지 정책은 1~2배만 허용하고 정확한 위험 확인과 변경 사유·리비전을 요구한다. 확인 문구와 자격정보는 SQLite에 저장하지 않는다.
- 전략 보호 잠금 알림은 결정 ID와 트리거 기준으로 멱등 저장하며 잠금 중에도 포지션 감축과 주문 취소는 허용한다.
- 선물 일일정산·만기·수동 롤오버를 별도 append-only 사건으로 기록하고 자동 롤오버와 실전 주문을 금지한다.
- 토스증권 연결 오류에서 자격정보, IP 권한, 호출 제한과 공급자 점검을 구분하는 분류를 추가했다.
- 주문 거부·부분 체결·시세 지연·증권사 장애·손실 한도·원장 불일치의 격리 운영 훈련을 추가했다. 훈련은 실주문을 전혀 보내지 않고 신규 진입 차단 여부와 취소 허용, 킬 스위치 대응 절차를 불변 이력과 운영 알림으로 저장한다.
- 홍보부 원고는 제목·본문·미디어·링크·마스킹을 SQLite 리비전으로 저장한다. 최신 리비전의 대표 승인만 수동 게시 패키지로 내보낼 수 있고 원고를 수정하면 이전 승인은 자동 무효화된다.
- 비정상 종료된 회의의 부분 보고를 보존하면서 손실된 Codex 실행은 다시 붙이지 않는 복구 표시를 `App.tsx`에서 별도 컴포넌트와 순수 판정 함수로 분리하고 프론트엔드 회귀 테스트를 추가했다.
- 24시간 길이의 합성 타임라인을 재생해 중복 후보·공급자 장애·메모리·타이머·SQLite 증가량을 검사했다. 합성 타임라인은 실제 24시간 경과 완료 증거로 기록하지 않는다.

## 계속 진행 중인 항목

- 24시간 섀도우 soak 완료 판정은 실제 24시간 표본이 있어야 하므로 검사 도구 구현만으로 완료 처리하지 않는다.
- Codex App Server 장시간 실제 회의 반복 검수는 로컬에서 실제 실행 기록을 축적해야 한다.
- 위험·거래품질·코인 담당자의 24시간 무중단 판정은 실제 연속 운영 계측이 필요하다.
- 공식 선물 상품 마스터·거래 캘린더·증거금 규칙은 공급자 연결 전까지 사용자 입력 sandbox와 분리한다.
- 시장별 휴장·조기종료 공식 캘린더는 공급자 없이 임의 생성하지 않는다.

## 안전 경계

- 외부 계정·자격정보를 읽거나 변경하지 않았다.
- 실전 주문 전송과 티스토리 자동 게시를 추가하지 않았다.
- 서로 다른 통화의 위험을 환율 없이 합산하지 않는다.
- 외부 응답의 재시도는 조회 요청으로 제한하고 변경 요청은 멱등성 대사 후 사용자가 판단한다.
- 원고 패키지 내보내기는 프론트의 승인 불리언을 신뢰하지 않고 SQLite의 최신 승인 리비전과 마스킹 상태를 서버에서 다시 확인한다.
