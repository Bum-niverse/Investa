# 1~5번 엔진 기반 구현 기록

## 범위와 안전 경계

이번 단계는 계좌 자격정보나 외부 주문 권한 없이 개발 가능한 결정론적 백엔드 기반을 완성한다. 실제 시세 공급자, 실제 증권·거래소 주문, 자동 홍보 발행과 학습 모델 자체는 활성화하지 않는다. 모든 확률·추천·실행 후보는 입력 부족 시 값을 꾸며내지 않고 차단 사유를 반환한다.

## 1. 데이터·선별·의사결정·위험·실행·성과·운영

- point-in-time 기록은 사건 시각, 공개 가능 시각, 수집 시각을 분리하고 미래 정정치·중복·오래된 공급자를 차단한다.
- 종목군과 선별 규칙은 버전 ID를 요구하고 거래정지·관리·상장폐지·과도한 스프레드를 제외한다.
- 전문가 보고서는 근거 ID, 반대 근거, 무효화 조건을 요구한다. Bull/Bear 토론은 서로의 주장 ID를 직접 다루며 라운드·토큰 상한을 가진다.
- 거래 계획은 방향, 진입, 손절, 목표, 최대 손실 기반 수량을 구조화한다. 보수적 위험 패널의 거부는 다른 패널이 덮어쓸 수 없다.
- 사전 주문 검사는 각 규칙 ID, 측정값, 한도와 시각을 기록한다. 수량·유동성·오래된 시세·가격 괴리·명시적 비용 검사를 통과하지 못하면 주문 후보를 만들지 않는다.
- 주문은 승인·제출·접수·부분체결·체결·취소·거부·만료 전이만 허용하고 사건 재생으로 현재 상태를 복원한다.
- 성과는 총손익, 비용, 순손익과 실현·미실현 손익을 분리한다. 전략·레짐별 귀속은 원본 체결 이력을 다시 쓰지 않는다.
- 감사 사건·중복 억제 알림·서비스 건강 상태·일관된 SQLite 백업 계약을 제공한다.

## 2. 뉴스·커뮤니티 데이터

- 공식/언론/커뮤니티 자료의 공개 시각과 수집 시각을 동일한 point-in-time 규칙으로 검사한다.
- 커뮤니티 반응은 중복·봇 의심·홍보성 비율과 함께 집계하며 사실 근거와 분리한다.
- 현재 범위에는 특정 Telegram 방 또는 유료 뉴스 공급자의 수집 어댑터가 포함되지 않는다. 합법적 API·내보내기 입력이 연결되기 전에는 수집 완료로 표시하지 않는다.

## 3. 코인 현물·무기한 선물 기반

- 현물, USDT 선형, 코인 역선형 제품 명세를 버전으로 고정한다.
- last·mark·index 가격과 funding 시각을 분리한다.
- 현물은 최소 주문금액, 수량 단위, 비용, 잔고와 총 노출을 검사한다.
- 무기한 선물은 격리증거금, 최대 2배, reduce-only, 청산 완충, 일일 손실, 총 명목가와 변동성 상한을 검사한다.
- heartbeat, WebSocket·REST 시각, 원장·잔고·포지션·주문·체결·funding 대사가 어긋나면 자동화 준비 상태를 해제한다.

## 4. 모델 적용 기반

- 국내·미국 주식, 주식·지수선물, 코인 현물·무기한 선물에 공통인 자산 계약을 정의한다.
- 모델 입력은 시점 고정 feature와 label을 사용하고 중복 N:N 병합과 미래 정보 누수를 검출한다.
- 방향 확률, 추천 확신도, 모델 신뢰도를 서로 다른 값으로 저장한다. 입력이 부족하거나 보정이 검증되지 않으면 `unavailable_reason`을 요구한다.
- OOS에서 Brier score, log loss와 ECE를 계산한다. 통과한 모델도 내부 모의나 실주문이 아니라 shadow 후보로만 승격한다.
- Walk-forward에는 학습 구간만으로 맞춘 두 상태 변동성 Markov 진단과 독립 상태 기준 OOS 비교를 추가했다.
- 같은 데이터셋의 전체 실험 카탈로그와 원시 OOS 수익률이 충분한 경우에만 Deflated Sharpe를 계산한다.

학습기, hyperparameter search, 모델 파일 registry와 online inference server는 후속 범위다. 이 기반은 특정 모델의 정확도나 수익률을 보장하지 않는다.

## 5. 개발기·홍보 안전 기반

- 실제 개발 사건과 근거 파일로만 개발기 초안을 만든다. 테스트·보안·기능 상태가 불완전하면 완료나 수익 보장을 표현하지 않는다.
- 이미지·영상은 출처, 라이선스, 합성 여부와 모바일 검수를 요구한다.
- 초안 수정은 새 revision을 만들고 기존 승인을 무효화한다. private 저장은 idempotency key로 중복을 막는다.
- Tistory·GitHub 원격 발행은 별도 사용자 승인과 자격정보 연결 전까지 구현하지 않는다.

## 검증 기준

- 정상, 경계, 실패와 미래 정보 누수 테스트
- 백테스트 및 Walk-forward 재현 테스트
- Rust 전체 단위 테스트, clippy, format, Tauri/프론트 빌드
- 실제 계좌·실주문·외부 발행은 검증 대상에서 제외

## 2026-08-25 통합 실행 묶음

- `engine_runs` 불변 실행 기록을 SQLite schema v12에 추가했다. 실행 ID, 멱등성 키, 입력 JSON, 전체 단계 보고서, 후보 준비 여부와 상태를 함께 저장한다.
- 동일 멱등성 키와 동일 입력은 기존 결과를 재생하고, 다른 입력은 거부한다. 완료된 후보는 취소할 수 없으며 차단·중단 실행의 취소는 원본 행을 수정하지 않고 append-only 상태 사건으로 남긴다.
- 통합 실행은 point-in-time 데이터 품질, 커뮤니티 심리 분리, 유니버스 스크리닝, Bull/Bear 반론, 거래 계획, 3관점 위험 심의, 결정론적 사전 주문 검사를 순서대로 평가한다.
- 어느 단계든 실패하면 `blocked`와 구체적인 차단 사유를 저장한다. 모든 단계가 통과해도 결과는 **내부 모의주문 후보 준비**일 뿐이며 실주문 전송은 항상 `false`다.
- 뉴스·재무·시장 데이터와 커뮤니티 입력을 표준 계약으로 정규화하는 preview 파이프라인을 추가했다. 원문은 저장하지 않고 SHA-256 지문만 넘기며, 사실 근거에 심리 점수를 섞는 입력은 거부한다.
- 모의 원장 `성과 분석` 화면에 통합 실행 수, 후보 준비 수, 차단·중단 수, 최근 차단 사유, 취소 가능한 실패 실행을 표시한다. 확률은 기존 분석 화면의 최소 표본 게이트를 통과한 경우에만 표시한다.

### 완료로 보지 않는 항목

- 외부 뉴스·커뮤니티 공급자의 원격 수집 권한과 약관 검증
- KIS 등 실제 증권사 모의계좌 주문·취소·대사
- 실계좌 주문, 자동 발행, 모델 학습기와 온라인 추론 서버
- UI에서 통합 실행 요청 본문을 직접 작성하는 고급 편집기
