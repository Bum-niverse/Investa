# 연구·백테스트·내부 모의계좌 엔진

기준일: 2026-08-21

## 구현 범위

실제 주문, 유료 데이터와 외부 저장소 코드 실행 없이 다음 도메인 경계를 구현했다. 토스증권 Open API는 종목 캔들·현재가·계좌·보유자산을 읽기 전용으로 사용한다.

1. `ReferenceEvidence`와 `ResearchReport` 근거 검증
2. 공통 `StrategySpec` 후보와 실행 가능성 검증
3. 시점 정합 가격 봉을 사용하는 결정론적 이동평균 교차 백테스트
4. 명시적으로 전달받은 수수료·세금·슬리피지 비용 계산
5. append-only 사건을 재생해 잔고·포지션·실현손익을 계산하는 내부 모의계좌
6. Codex 구조화 연구 보고서에서 토스증권 일봉 탐색 백테스트까지 이어지는 Tauri 수직 흐름
7. 연구 보고서·정규화 가격봉·설정·결과의 원자적 SQLite 저장과 최근 기록 조회

현재 구현은 사용자가 승인한 위험 정책이 없으면 투자 성과를 합격 또는 탈락으로 판정하지 않는다. 승률, 수익률, MDD, 평균 거래 손익과 Profit Factor는 관측 결과다.

## 연구 근거와 StrategySpec

저장소 근거는 HTTPS URL뿐 아니라 고정 commit 또는 tag인 `revision`이 필요하다. 전략은 보고서에 실제로 포함된 근거 ID만 참조할 수 있다.

`StrategySpec`에는 다음이 포함된다.

- schema version, 전략 ID와 이름
- 시장, 종목과 통화
- 검증할 가설
- 근거 ID
- 명시적인 진입·청산 신호
- 알려진 한계와 미해결 항목

미해결 항목이 남아 있으면 구조적으로 유효한 후보일 수는 있지만 `executable=false`가 된다. 외부 레포 코드는 내려받거나 실행하지 않는다.

퀀트 논문 연구원 요청에 `https://github.com/{owner}/{repo}`가 포함되면 최대 2개 공개 저장소만 GitHub API로 조회한다. 요청 대상은 검증한 owner/repo에서 서버가 직접 구성하므로 임의 URL·redirect·사설망으로 요청하지 않는다. 공개 저장소 URL, HEAD commit, 기본 branch, 라이선스 후보, archived 여부, 설명과 최대 3,000자의 README 발췌만 Codex 입력에 첨부한다. 외부 내용은 신뢰할 수 없는 근거로 구획하고 그 안의 명령은 실행하지 않으며, 수집 실패는 unknown으로 남긴다.

현재 실행 가능한 첫 신호는 이동평균 교차 하나다. 이는 전략 성과 기준이 아니라 고정 fixture로 전체 흐름을 검증하기 위한 최소 플러그인이다. fast·slow 기간은 기본값 없이 `StrategySpec` 입력으로만 받는다.

## 시점 정합 백테스트

각 `PriceBar`는 다음 시각과 단위를 보존한다.

- `periodStartMs`, `periodEndMs`: 가격 봉 구간
- `availableAtMs`: 공급자가 데이터를 공개한 시각
- `ingestedAtMs`: Investa가 데이터를 실제로 수집한 시각
- `source`, `symbol`, `currency`
- 통화 최소 단위의 시가·종가와 거래량

신호는 현재 봉 종가까지로 계산하고 다음 봉 시가에만 체결한다. 신호 봉의 원천 `availableAtMs`가 다음 봉 시작보다 늦으면 미래정보 누수 위험으로 실행을 거부한다. `ingestedAtMs`는 다운로드·감사 시각으로 별도 보존하며 과거 판단 가능 시각으로 오용하지 않는다. 종목·통화 혼합, 중복·역순·겹침 봉, 0 가격과 잘못된 시각도 거부한다.

토스 캔들은 최신순 응답을 시간 오름차순으로 정규화하고 KRW는 원, USD는 센트로 변환한다. 진행 중인 미완료 봉은 제외하며, 일봉의 고정 24시간 간격을 가정하지 않고 다음 실제 봉 시작 시각으로 구간 경계를 보정한다.

## Codex → 토스 탐색 백테스트

퀀트 논문 연구원에게 지시하면 `turn/start.outputSchema`가 최종 응답을 `ResearchReport` 계약으로 제한한다. Rust는 응답을 다시 역직렬화하고 근거 URL·리비전·신호·미해결 항목을 검증한다. `executable=true`인 후보만 다음 고정 탐색 설정으로 토스 캔들 조회를 실행한다.

- 최신 최대 200개 수정주가 일봉
- 1주 단위
- KRW 1억원 또는 USD 10만 달러의 가상 초기 현금
- 비용 0bp
- 기간 말 미청산 포지션 강제청산

이는 연결 검증용 가정이며 성과 합격 기준이나 운영 위험 정책이 아니다. UI에 가정을 항상 표시하고 비용 0bp 결과는 전략 승격 근거로 사용할 수 없다고 경고한다.

## Codex → 업비트 탐색 백테스트

`market=crypto`, `currency=KRW`, `KRW-` 코드인 연구 계약은 업비트 공개 API의 최신 최대 200개 완료 일봉으로 실행한다. KST 일봉 경계와 24시간 시장임을 경고에 보존하고, 기본 5bp 매수·매도 수수료와 1억 분의 1 코인 고정소수점 수량을 사용한다. 기본 검증 수량은 0.1코인이다. 수동·지정가 대기·섀도우 후보와 내부 원장도 같은 base unit과 수량 scale을 사용한다.

백테스트 입력에는 experiment ID, dataset ID, code version, 초기 가상 현금, 주문 수량, 종료 청산 여부와 비용 모델이 모두 명시되어야 한다. 같은 입력은 같은 체결과 결과를 만든다.

### 저장 실험 복제·재실행

- 분석 보관함에서 실행 가능한 저장 실험을 선택하고 이동평균 기간, 초기자금, 수량, 비용과 종료 청산 조건을 바꿔 재실행한다.
- 손절·익절·일일손실 한도는 세 값을 모두 입력하거나 모두 비운다. 사용한 위험 조건은 `BacktestConfig.riskLimits`에 함께 저장해 다시 재생할 수 있게 한다.
- 원본 `record_json`과 가격봉 스냅샷은 수정하지 않는다. 동일 `datasetId`를 재사용하고 새 trace·strategy·experiment ID로만 저장한다.
- 복제본 분류는 항상 `research_experiment`이며 원본·복제본 수익률, 최대 낙폭, 승률과 실현손익을 나란히 보여준다.
- 복제본은 성과가 좋아도 승격 후보나 모의주문 후보로 자동 전환하지 않는다.

## 비용 모델

`TradingCosts`는 다음 값을 basis point 단위로 받는다.

- 매수 수수료
- 매도 수수료
- 매도 세금
- 슬리피지

매수에는 불리한 상향 슬리피지, 매도에는 불리한 하향 슬리피지를 적용한다. 수수료와 세금은 최소 통화 단위로 올림하며 계산 overflow와 비정상 비용을 거부한다. 실제 증권사별 비용값은 아직 정하지 않았다.

## 내부 모의계좌 원장

`AppendOnlyLedger` 인터페이스, 테스트용 `InMemoryLedger`와 재시작 가능한 `SqliteLedger`를 구현했다. 사건은 계좌 개설과 즉시 모의 체결만 지원한다.

앱 최초 실행 시 KRW 1억원 계좌를 한 번만 개설한다. 설정 화면의 수동 모의체결은 토스 현재가를 기준 가격으로 읽되 결과를 SQLite 원장에만 기록한다. 첫 구현의 비용은 0bp로 명시하며, 연구원이 비용 정책을 백테스트하기 전까지 성과 승격 근거로 사용하지 않는다.

- 계좌 ID, 기준 통화와 초기 가상 예수금
- 주문 ID와 idempotency key
- 종목, 매수·매도, 수량과 기준 가격
- 실제 적용한 비용 모델과 재현된 체결 가격·수수료·세금
- 사건 발생 시각

원장 재생은 중복 주문, 중복 idempotency key, 시각 역행, 계좌·통화 불일치, 잔고 부족, 보유량 초과 매도, 금액 변조와 overflow를 검사한다. 부분 매도 시 보유 원가를 비례 배분하고 실현손익을 다시 계산한다.

SQLite 원장은 사건 순번을 복합 기본키로 저장하고 기존 사건의 수정·삭제 API를 제공하지 않는다. append 직전 DB 사건 수와 메모리의 예상 순번이 다르면 동시 변경으로 보고 거부한다. 재시작 시 사건 JSON을 시간순으로 읽은 뒤 전체 원장을 재생해 변조·역순·도메인 불일치를 먼저 검사한다.

## 영속 연구 기록

성공한 탐색 백테스트는 Tauri 앱 데이터 폴더의 `investa.sqlite3`에 다음 세 묶음으로 저장한다.

- `research_reports`: 추적 ID, 검증 결과와 전체 구조화 보고서
- `datasets`: 공급자·종목·통화·간격·수정주가 여부와 정규화 가격봉 스냅샷
- `backtest_runs`: 실험 ID, 명시적 설정, 결과 지표, 경고와 전체 재현 레코드

세 레코드는 하나의 트랜잭션으로 확정된다. 같은 식별자와 같은 내용의 재시도는 중복 없이 성공하고, 같은 식별자에 다른 내용이 들어오면 전체 트랜잭션을 거부한다. SQLite는 foreign key, `STRICT` 테이블, WAL, 5초 busy timeout과 시작 시 `quick_check`를 사용한다. 원천 자격증명은 저장 대상에서 제외한다.

## 분석 보관소 조회 계약

- `analysis_record_history`는 저장된 백테스트, 실행 차단 연구와 회의 종합을 결합해 종류·상태·시장·종목·완료 시각을 반환한다.
- 분석 가격대는 현재 정규화 `PriceBar`가 보존하는 각 봉의 시가와 종가 중 최솟값~최댓값이다. 일중 고가·저가는 연구용 `PriceBar` 계약에 포함되지 않으므로 고가·저가 범위처럼 표시하지 않는다.
- `analysis_record_detail`은 선택한 실험 ID와 동일한 불변 `ResearchReport`, 검토 결과, 설정, 결과와 경고를 반환한다.
- schema v6은 일반 분석 노트와 승인 이력을 가진 위험 정책 버전을 추가한다. schema v4부터 백테스트 요청 시각을 nullable 필드로 저장하며 이전 기록의 요청 시각은 임의 보정하지 않는다.
- `전략`과 `국장/미장/코인`은 같은 기록의 종류와 시장을 각각 필터링하는 축이다. 코인 기록은 코인 백테스트 어댑터가 저장한 뒤에만 나타나며 UI가 빈 결과를 가짜 데이터로 채우지 않는다.

## 보안 경계

- Tauri IPC에는 검증된 `ResearchReport`와 명시적 백테스트 설정을 받는 읽기 전용 `toss_run_research_backtest`만 노출했다.

### 외부 레퍼런스 선별 재구현

- FinPilot의 연속 봉·Bollinger 조건부 통계는 고정 commit `dca1e4b4ca280a28b3b6c40380c1e06adad5532d`를 출처로 기록하고 Rust 순수 함수로 재구현한다. Python·pandas·yfinance를 런타임 의존성으로 추가하지 않는다.
- 현재 연속 봉과 정확히 같은 과거 구간만 집계하며, 각 과거 구간 뒤에 실제로 존재했던 봉만 결과로 사용한다. 현재 시점 뒤의 봉은 입력에 포함되지 않는다.
- 다음 봉은 양봉·음봉·도지, 1·3·5·20봉 horizon은 기준 종가 대비 상승·하락·보합으로 분리한다.
- 동일 조건 표본이 20회 미만이면 확률과 Wilson 95% 구간을 공개하지 않는다. 표본 수와 원시 count는 보존한다.
- Bollinger 상·하단 사건은 다음 봉에서 관측되는 돌파·반전 또는 반등·이탈을 집계한다. 봉 내부 순서를 추정하지 않는다.
- TradingAgents의 미병합 백테스트 PR 코드는 포함하지 않는다. 대신 불변 실험 ID를 통한 안전한 동일 재시도, 가격 벤치마크 대비 알파, Sharpe·Sortino·변동성 평가 계약을 Investa 구조에 맞게 자체 구현한다.
- 가격 벤치마크는 시장지수가 아니라 같은 입력 구간의 해당 종목 첫 종가 대비 마지막 종가다. 화면에 이를 명시해 시장 알파로 오해하지 않게 한다.
- 토스증권 자격증명은 기존 Windows 자격 증명 관리자에서 Rust가 읽으며 React로 반환하지 않는다.
- Codex에는 계좌·잔고 API, 파일 쓰기와 실제 주문 함수가 없다. 토스 계좌·보유자산은 전용 Rust command만 읽고 계좌번호를 마스킹하며 `accountSeq`를 React에 반환하지 않는다.
- React가 투자 정책이나 원장 사건을 직접 변경할 수 없다.
- 입력은 길이·형식·중복·시간·통화·산술 경계를 검증한다.
- 연구 기록 IPC는 최근 100개 이하 조회와 특정 실험 상세 읽기만 제공하며 수정·삭제 명령을 노출하지 않는다.

## 현재 제한과 다음 단계

- 저장된 백테스트 결과를 승인 대기 섀도우 주문 후보로 승격하고, 사용자 승인 후 내부 원장에만 체결하는 오케스트레이터를 연결했다.
- 주문 후보 상태 머신과 로컬 지정가 대기·취소를 구현했다. 부분체결·정정과 원격 취소는 외부 모의 브로커 대사가 필요해 보류한다.
- 회의 진행률은 Codex 작업·계약 검증 사건과 연결했지만, 회의 종합만으로 실행 가능한 전략을 임의 생성하지 않으므로 구조화 연구·백테스트가 별도로 필요하다.
- 다음 단계는 내부 주식선물·지수선물 sandbox에 공식 상품 마스터, 일일정산, 만기·롤오버를 추가하고 장시간 섀도우 복구를 검증하는 것이다.
