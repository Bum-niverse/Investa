# KIS 모의투자 연결 준비

> 현재 상태: 사용자 결정에 따라 한국투자증권 계좌 개설, 모의계좌 발급과 외부 서버 검증을 보류합니다. Investa 내부 주식·코인·선물 sandbox 개발은 이 자격정보 없이 계속 진행합니다.

사용자가 말한 `KSI`는 문맥상 한국투자증권 `KIS Open API`를 뜻합니다. Investa는 KIS 모의 자격정보 검증·Windows 자격 증명 관리자 저장, 모의 토큰·HashKey, 국내 잔고, 사용자 확인형 국내 모의주문·취소와 당일 체결조회까지 구현했습니다. 실전 도메인과 실전 주문은 컴파일 경계에서 계속 제외합니다.

## 사용자가 준비할 항목

1. 한국투자증권 계좌와 연동된 HTS ID
2. KIS Developers에서 Open API 서비스 신청
3. 모의투자용 App Key와 App Secret
4. 모의계좌번호 앞 8자리
5. 상품코드 2자리(일반적인 주식 계좌는 `01`, 실제 발급 정보로 확인)

비밀값은 Investa 설정 화면에 로컬로 입력해야 하며 채팅, 문서, Git, 로그에 넣지 않습니다.

## 공식 모의투자 환경

- REST 기본 주소: `https://openapivts.koreainvestment.com:29443`
- 실전 주소와 키를 혼용하지 않습니다.
- 한국투자증권 공식 예제의 `paper_app`, `paper_sec`, `my_paper_stock`, `my_prod`에 대응하는 값을 별도 보관합니다.
- 모의투자는 실전보다 호출 제한이 낮을 수 있으므로 조회·주문 모두 rate limit과 재시도 상한을 둡니다.

## Investa 구현 순서

1. ~~Windows 자격 증명 관리자에 KIS 모의 키 저장·삭제~~ 완료
2. ~~모의 도메인 토큰·국내 잔고 조회~~ 완료
3. ~~명시적 확인형 국내 모의주문·취소·당일 체결 조회와 요청 ID 감사 기록~~ 완료
2. 토큰 발급과 만료 전 갱신
3. 모의계좌 잔고·보유종목 읽기 전용 조회
4. 주문 전송 없는 주문 요청 검증과 중복 방지 검사
5. 사용자가 명시적으로 승인한 1주 모의주문
6. 주문 조회·취소·정정과 체결 대사
7. 내부 SQLite 모의원장과 KIS 모의계좌 결과를 분리 표시

왼쪽 `모의` 터미널의 `KIS 모의계좌 연결 준비`에서 모의 App Key·Secret, HTS ID, 계좌번호 앞 8자리와 상품코드 2자리를 입력합니다. 계좌번호만으로는 인증할 수 없습니다. 저장 성공은 자격정보 형식과 로컬 보관 완료를 뜻하며 KIS 서버 연결 성공이나 주문 권한 활성화를 뜻하지 않습니다.

실전 URL과 실전 키는 이 단계에 포함하지 않습니다. Codex 부서 보고와 본부장 종합 결과도 KIS 자격정보나 주문 함수를 직접 받지 않습니다.
